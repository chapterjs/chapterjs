Every version of `chapterjs`, `create-chapter` and `create-chapterjs` has the same number. Only `chapterjs` lives in your project; `chapterjs dev` tells you when a newer one is out. To update it:

<CodeGroup>

```bash pnpm
pnpm update chapterjs --latest
```

```bash npm
npm install chapterjs@latest
```

```bash yarn
yarn add chapterjs@latest
```

```bash bun
bun add chapterjs@latest
```

</CodeGroup>

<Update label="0.2.3" description="Storage, five templates, and a new project on the version of create chapter, exactly">

Your bot can keep what it learns: `export const warnings = store<Warning[]>({ expires: '30d' })` declares a [store](/storage), per server unless `scope: 'global'`, typed by what it holds, with an expiration if you want one. In a command or an event, the key is yours and the server is known; elsewhere, `warnings.in(guild)`. One JSON file per store in `data/`, written for you, and shared by every process of a large bot.

`create chapter` now offers five [templates](/setup/project-structure#templates). `default` is one file, the `ready` event, and the tutorial starts from it. The others are complete bots: `tickets` (support tickets in private threads), `music` (a player with a queue and buttons), `community` (welcome cards, roles people pick, weekly stats) and `moderation` (timeouts, purge, slowmode, lock, and a log of every action). The `/ping`, `/hello`, `/play` and moderation examples of the old template are gone: what they showed is in the new ones and in the guide.

`create chapter` also writes the exact version of `chapterjs` in your `package.json` (`"0.2.3"`, no `^`): `pnpm create chapter@0.2.3` gives a project on `chapterjs@0.2.3`, and your project only changes version when you run the command [`chapterjs dev` gives you](/run/dev#a-new-version-of-chapterjs).

</Update>

<Update label="0.2.2" description="A lighter default template">

The project made by `create chapter` no longer ships the moderation example (`/ban`, `/kick`, `/warn`): it keeps `/ping`, `/hello`, `/play`, the two events, the presence and the two languages.

</Update>

<Update label="0.2.1" description="chapterjs dev tells you when a new version is out">

Once the bot is online, `chapterjs dev` says when a newer version of `chapterjs` is published, with the command that installs it, written for the package manager of your project. npm is asked at most once a day, and never holds the bot. See [A new version of ChapterJS](/run/dev#a-new-version-of-chapterjs).

</Update>

<Update label="0.2.0" description="Your files, your order: the framework reads what they export">

Nothing is tied to a folder any more. Every file of `src/` is loaded, and what it exports made with `command()`, `event()`, `button()`, `select()`, `modal()`, `embed()`, `task()`, `presence()` or `language()` is what the bot runs: a file may declare several things, and sit wherever you like. See [Project structure](/setup/project-structure).

- **[Commands](/commands)** take a `name`: `command({ name: 'ping', ... })`, `'mod ban'` for a subcommand. Two commands with the same name are reported, wherever they are.
- **[Events](/events)** take a `name` too, which types what `run` receives: `event({ name: 'memberJoin', run({ member }) { ... } })`. The options are written next to it (`bots: true`, `where: 'dm'`), and a typo in either is underlined.
- **[Components](/components)** and **[tasks](/tasks)** are named by their export: `export const again = button(...)` is the button `again`. Moving a file changes nothing; renaming the export does, as renaming the file did.
- **[Languages](/translated-messages)** say their `locale`: `language({ locale: 'fr', ... })`, and a second `default: true` is underlined in both files. A language may be declared in several places: the texts of a feature live next to it, and `t` offers them all. A text the default language does not have is taken from the language that has it, so a module written in other languages than yours still works.
- `.chapterjs/` is one TypeScript project for the whole of `src/`, and holds only what the project adds: the files of `public/`, the languages and the commands. The folders in parentheses and the `_` files are not needed any more: a folder is only a folder, and a file that declares nothing is yours.

The types `EventFile`, `CommandFile`, `ButtonFile`, `SelectFile`, `ModalFile`, `EmbedFile`, `TaskFile`, `PresenceFile` and `LanguageFile` are now `EventDeclaration`, `CommandDeclaration`, `ButtonDeclaration`, `SelectDeclaration`, `ModalDeclaration`, `EmbedDeclaration`, `TaskDeclaration`, `PresenceDeclaration` and `LanguageDeclaration`.

</Update>

<Update label="0.1.4" description="The first version of the framework">

A folder of files becomes a Discord bot.

- **[Commands](/commands)**: a file of `src/commands/` is a slash command, with typed options, choices, [autocomplete](/commands/options#autocomplete), permissions, cooldowns and translations.
- **[Events](/events)**: a file of `src/events/<event>/` runs when it happens. The intents follow from the files you write.
- **[Components](/components)**: buttons, select menus, forms and embeds in `src/components/`, with typed `data` and no id to write.
- **[Tasks](/tasks)**: what the bot does by itself, every so often or at set times.
- **[Voice](/voice)**: the bot joins a voice channel and plays a file of `public/`, a file sent on Discord or a link, end-to-end encrypted as Discord asks.
- **[Presence](/presence)**: what the bot shows under its name, in `src/presence.ts`.
- **[Translated messages](/translated-messages)**: one file per language in `src/messages/`, and `t` speaks the language of the readers.
- **[`chapterjs dev`](/run/dev)**: the bot on a test server, every file reloaded when you save it.
- **[`chapterjs build`](/run/build)** and **[`chapterjs start`](/run/start)**: one compiled file for production, run on several processes when the bot is large.
- **[`create-chapter`](/quickstart)**: a new project in one command.
- **[Node.js 24](/quickstart)** or newer: `chapterjs` and `create-chapter` stop at once on an older one and say what to install.

</Update>
