Options are what people fill in after the name of a command. Declare them as an object, and `run` receives their values **already typed**: you never write a type.

```ts src/commands/mod/ban.ts
import { command } from 'chapterjs';

export default command({
  description: 'Bans a member',
  permissions: ['BanMembers'],
  options: {
    target: { type: 'user', description: 'Who to ban', required: true },
    reason: { type: 'string', description: 'Why', maxLength: 200 },
    days: { type: 'integer', description: 'Days of messages to delete', min: 0, max: 7 },
  },
  async run({ interaction, options, guild }) {
    // options.target: User
    // options.reason: string | undefined
    // options.days: number | undefined
    await guild.ban(options.target, {
      reason: options.reason,
      deleteMessageSeconds: (options.days ?? 0) * 86_400,
    });
    await interaction.reply(`Banned ${options.target.displayName}.`);
  },
});
```

That is all: Discord asks for `target`, `reason` and `days` in that order, and your editor knows that `options.target` is a `User` and that `options.reason` may be missing.

<Note>
  Every field of every kind of option is in the [reference](/reference/command#the-options).
</Note>

## Declaring an option

The key is the name of the option, the value says what it is. Every option has a `type` and a `description` (1 to 100 characters, shown under its name):

| `type` | What the person fills in | What `run` receives |
| --- | --- | --- |
| `'string'` | A text | `string` |
| `'integer'` | A whole number | `number` |
| `'number'` | Any number | `number` |
| `'boolean'` | True or false | `boolean` |
| `'user'` | A user | [`User`](/reference/user) |
| `'role'` | A role | [`Role`](/reference/role) |
| `'channel'` | A channel | [`Channel`](/reference/channels) |
| `'mentionable'` | A user or a role | `User \| Role` |
| `'attachment'` | A file | [`Attachment`](/reference/data#attachment) |

Names follow the rules of Discord: lowercase letters, digits, `-` and `_`, 32 characters at most. A command has 25 options at most.

## Required or optional

An option is **optional** unless it says `required: true`. In `run`, a required option is always there; an optional one may be `undefined`, and your editor reminds you:

```ts src/commands/greet.ts
import { command } from 'chapterjs';

export default command({
  description: 'Greets someone',
  options: {
    who: { type: 'user', description: 'Who to greet', required: true },
    message: { type: 'string', description: 'What to say' },
  },
  async run({ interaction, options }) {
    // options.who: User
    // options.message: string | undefined
    await interaction.reply(`${options.message ?? 'Hello'}, ${options.who.displayName}!`);
  },
});
```

Discord wants the required options first. You can declare them in any order: ChapterJS puts the required ones first for you, and keeps the order you wrote for the rest.

## Choices

With `choices`, the person picks in a list instead of typing, and the value is typed as one of the choices. A `string`, `integer` or `number` option can have between 1 and 25 choices:

```ts src/commands/color.ts
import { command } from 'chapterjs';

export default command({
  description: 'Picks a color',
  options: {
    // A list: what the person sees is what your code receives.
    color: { type: 'string', description: 'Your color', choices: ['red', 'green'], required: true },
    // An object: the key is shown, the value is received.
    size: { type: 'integer', description: 'How big', choices: { Small: 1, Large: 2 } },
  },
  async run({ interaction, options }) {
    // options.color: 'red' | 'green'
    // options.size: 1 | 2 | undefined
    await interaction.reply(`You picked ${options.color}.`);
  },
});
```

The choices of a `string` option are texts, those of an `integer` or `number` option are numbers; what is shown is 1 to 100 characters. The same choice can't appear twice.

## Autocomplete

When the values are not known in advance, or change (a song, a player, a ticket), `autocomplete` suggests them **while the person types**: Discord asks your bot every few keystrokes, and shows what your function returns under the option. The person may still type something else.

```ts src/commands/play.ts
import { command } from 'chapterjs';

const SONGS = [
  { id: '1', title: 'Daylight' },
  { id: '2', title: 'Dark Horse' },
  { id: '3', title: 'Darkside' },
];

export default command({
  description: 'Plays a song',
  options: {
    song: { type: 'string', description: 'Which song', required: true },
  },
  autocomplete: {
    // Called while the person types in "song", with what they typed so far.
    song: ({ value }) =>
      SONGS.filter(song => song.title.toLowerCase().startsWith(value.toLowerCase()))
        // Shown as the title, received as the id.
        .map(song => ({ name: song.title, value: song.id })),
  },
  async run({ interaction, options }) {
    // options.song: string, the id of the song, or whatever was typed
    const song = SONGS.find(song => song.id === options.song);
    await interaction.reply(song ? `Playing ${song.title}.` : 'I do not know that song.');
  },
});
```

`autocomplete` has one function per option, by its name, for a `string`, `integer` or `number` option without `choices`. It receives:

| Field | What it is |
| --- | --- |
| `value` | What the person typed so far: a text (maybe empty) for a `string` option; for an `integer` or `number` option, a number, or `undefined` while it is not one yet |
| `options` | What the person filled in so far, every option optional; a `user`, `role`, `channel`, `mentionable` or `attachment` option is its id |
| `user`, `locale` | Who is typing, and their language |
| `guild`, `member`, `channel` | Where, following `where` like `run` |
| `t` | The texts of the project, in the language of the person (see [translated messages](/translated-messages)) |

It returns the suggestions (or a promise of them): a value, shown as is, or `{ name, value }` to show a text and receive another value. A `string` option suggests texts, an `integer` or `number` option numbers. Discord shows 25 at most, in the order you return them, and waits 3 seconds: return quickly, your best matches first.

<Warning>
  A suggestion is a help, not a limit: Discord sends your `run` what the person typed, picked in the list or not. Check the value, as in the sample.
</Warning>

What the function returns is checked when it is sent. Too many suggestions are cut to 25, and a name over 100 characters is shortened, said once with `⚠`. What can't be fixed is an error, and nothing is suggested:

```text
✗ src/commands/play.ts A suggestion of /play song has the value 1: the option is a text, so its suggestions must be texts.
```

## Limits on what is typed

A text can be given a length, a number a range:

| Field | For | Meaning |
| --- | --- | --- |
| `minLength` | `string` | The shortest text accepted, in characters (0 to 6000) |
| `maxLength` | `string` | The longest text accepted, in characters (1 to 6000) |
| `min` | `integer`, `number` | The smallest value accepted |
| `max` | `integer`, `number` | The largest value accepted |

Discord refuses what is outside before the command even reaches your bot. For an `integer` option, `min`, `max` and the choices are whole numbers.

## Channels of some kinds only

`channelTypes` says which kinds of channels can be picked. By default, all of them:

```ts src/commands/announce.ts
import { command, ChannelType } from 'chapterjs';

export default command({
  description: 'Announces something in a channel',
  permissions: ['ManageGuild'],
  options: {
    channel: { type: 'channel', description: 'Where', channelTypes: [ChannelType.GuildText], required: true },
    text: { type: 'string', description: 'What to say', required: true, maxLength: 2000 },
  },
  async run({ interaction, options }) {
    if (!options.channel.isTextBased()) return interaction.reply('Pick a text channel.');
    await options.channel.send(options.text);
    await interaction.reply({ content: 'Done.', ephemeral: true });
  },
});
```

The values are those of [`ChannelType`](/reference/enums#channeltype). What `run` receives is still a [`Channel`](/reference/channels): check its kind with `isTextBased()` or `isVoice()` before using what only that kind has.

## What is checked

Everything an option declares is checked when the file loads, against the limits of Discord. A mistake is explained in your terminal before Discord refuses it, with the file in front:
