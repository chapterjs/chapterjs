---
title: 'chapterjs build'
description: 'Check your bot and compile it for production'
---

`chapterjs build` checks your bot and compiles it for production. Everything that can be wrong with your files is found here, before anything is online. It is what the `build` script of your project runs:

<CodeGroup>
```bash pnpm
pnpm build
```

```bash npm
npm run build
```

```bash yarn
yarn build
```

```bash bun
bun run build
```
</CodeGroup>

```text
✓ Types checked
✓ Built in .chapterjs/build: 4 commands, 6 events (18 kB)
ℹ Run chapterjs start to put it online.
```

Then [`chapterjs start`](/start) runs what was built. It does not need your token, and it never talks to Discord: you can run it anywhere, as often as you want.

## What it does

<Steps>
  <Step title="Checks the types">
    What your editor underlines, for the whole project at once. One error stops the build:

    ```text
    ✗ Your project has type errors, so it was not built:
      src/commands/ban.ts(12,25): error TS18047: 'message.member' is possibly 'null'.
    ```

    This uses the TypeScript of your project. If it is not installed where you build, the build says so and goes on.
  </Step>
  <Step title="Runs every file once">
    Each command and each event is loaded and checked, like `chapterjs dev` does when you save: a file in the wrong folder, an option without description, two files that are the same command...

    ```text
    ✗ src/commands/poll.ts The default export of this file must be what command() returns: import { command } from 'chapterjs'; export default command({ description: '...', run({ interaction }) { ... } })
    ✗ This file can't run, so your bot was not built. Fix it and build again: chapterjs dev shows the same errors while you write.
    ```
  </Step>
  <Step title="Compiles your bot">
    Your whole bot becomes **one JavaScript file**, in `.chapterjs/build`:

    - every command and event, with what they import from your project;
    - only what is used: code nothing calls is left out;
    - compact, so it loads fast.

    That file is what production runs.
  </Step>
</Steps>

A build that fails leaves nothing behind: there is never a half-built bot to start by mistake.

## Production runs the build, not your files

Once built, your bot does not change when you edit a file. The changes go online the next time you build:

```text
⚠ Your files changed since the last build: the bot runs the build, not your changes. Run "chapterjs build" to put them online.
```

So you can keep working in the same folder while your bot runs.

## Errors still name your files

The compiled file is not made to be read, but you never have to: when something fails in production, the error names the file and the line **you wrote**.

```text
✗ src/lib/levels.ts:42 Cannot read properties of undefined (reading 'xp')
```

The names of your functions and variables are kept too.

## What is in the build

| | In the build |
| --- | --- |
| Your commands and events | Yes |
| What they import from your project, wherever it is | Yes |
| Files and folders starting with `_`, when something imports them | Yes |
| Packages you installed | No: they stay in `node_modules`, which production needs too |
| Files your code reads while running (a JSON opened with `readFile`, an image...) | No: keep them next to your project |

## Nothing to install

The compiling is done by [esbuild](https://esbuild.github.io), which comes with ChapterJS: your project has nothing to add, and nothing to configure.

<Note>
  With **pnpm**, a project needs one more file, or pnpm refuses to install it: esbuild comes with an install script, and pnpm wants to be told what to do with it. `create chapter` writes that file for you. In a project made another way, create `pnpm-workspace.yaml` next to your `package.json`:

  ```yaml pnpm-workspace.yaml
  allowBuilds:
    esbuild: false
  ignoredBuiltDependencies:
    - esbuild
  ```
</Note>

## Putting your bot online

On the machine that hosts your bot:

<Steps>
  <Step title="Install">
    Copy your project there (without `node_modules`), then install its packages. Include the development ones if you want the build to check the types.
  </Step>
  <Step title="Build">
    Run the `build` script.
  </Step>
  <Step title="Start">
    Run the `start` script, with `BOT_TOKEN` given by your host: see [chapterjs start](/start).
  </Step>
</Steps>

Many hosts ask for a "build command" and a "start command": give them the `build` and `start` scripts of your project.

<Note>
  The `.chapterjs` folder is not saved in git. A host that takes your project from git builds it there; if you build on your computer and upload the result, upload `.chapterjs/build` too.
</Note>
