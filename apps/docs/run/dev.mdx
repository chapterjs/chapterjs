---
title: 'chapterjs dev'
description: 'Run your bot on your test server while you write it, with every file reloaded when you save'
---

`chapterjs dev` runs the bot of the current folder on your test server, and reloads your files when you save them. It is what the `dev` script of your project starts:

<CodeGroup>
```bash pnpm
pnpm dev
```

```bash npm
npm run dev
```

```bash yarn
yarn dev
```

```bash bun
bun dev
```
</CodeGroup>

```text
✓ Connected to My Server as my-bot
ℹ Intents computed from your files: GUILDS, GUILD_MESSAGES, MESSAGE_CONTENT
✓ 1 command, 2 events loaded
✓ Commands updated on My Server
```

That is all: the bot is online in your test server, your commands show up there, and every file of `src/` is watched. Everything the command needs from Discord is worked out from your files: the intents of the second line, what the bot [remembers](/memory), the commands to register.

<Note>The options, the environment variables and the exit codes of the command are in the [CLI reference](/reference/cli#chapterjs-dev).</Note>

## What it needs

A `.env` file at the root of your project, with two values:

```bash .env
BOT_TOKEN=
DEV_GUILD_ID=
```

Where to find them is in [Your Discord application](/setup/discord-application). A value set in the real environment wins over the file.

<Info>
  **`BOT_TOKEN` is the token of a dev application, not of the bot that goes online for everyone.** We recommend two applications from the start: one bot for your computer, one bot for production. With one bot for both, your test server shows every command you are changing twice, and the presence, the privileged intents and the token of production are shared with what you try. How to set it up: [A second bot for development](/run/start#a-second-bot-for-development).
</Info>

Without the file, the command stops before anything else:

```text
✗ There is no .env file in this folder.
  Copy .env.example to .env, then fill in BOT_TOKEN and DEV_GUILD_ID.
```

And it must run in the folder of your bot, the one with `package.json` and `src/`:

```text
✗ There is no src folder here.
  Run this command in the folder of your bot (the one with package.json), or create a project with "pnpm create chapter".
```

## What it checks for you

Before connecting, `chapterjs dev` makes sure everything is in place. When something is missing, it says what and how to fix it, and when you are in a terminal it waits for the fix instead of making you start again:

<AccordionGroup>
  <Accordion title="A value of .env is wrong">
    Every problem is printed at once: a value that is empty, still the example value, a token with a space in it, a server ID that is not made of digits. The command stops; fix `.env` and start it again.

    ```text
    ✗ .env: BOT_TOKEN is still the example value.
      Copy the token of your bot from https://discord.com/developers/applications → your application → Bot → Reset Token.
    ✗ .env: DEV_GUILD_ID is empty.
      In Discord, right-click your test server → Copy Server ID (enable Settings → Advanced → Developer Mode to see it).
    ```
  </Accordion>
  <Accordion title="The token is refused">
    Discord does not recognize the token, usually because it was reset. The command stops.

    ```text
    ✗ Discord refused the bot token. Copy it again from the Developer Portal (your application → Bot → Reset Token) into BOT_TOKEN in your .env file.
    ```
  </Accordion>
  <Accordion title="The bot is not in your test server">
    You get a link that adds the bot to that server, with every permission: a test server is a playground. Open it, confirm, and the command goes on by itself.

    ```text
    ⚠ Your bot is not in your dev server yet (DEV_GUILD_ID=123456789012345678).
      Open this link to add it:
      https://discord.com/oauth2/authorize?client_id=...&scope=bot+applications.commands&permissions=8&guild_id=123456789012345678&disable_guild_select=true
      If the link shows another server, DEV_GUILD_ID is not the ID of a server you manage.
      Waiting for the bot to be added...
    ✓ The bot joined My Server
    ```
  </Accordion>
  <Accordion title="A privileged intent is not enabled">
    Some [events](/events#intents-nothing-to-list) need an option enabled for your bot in the Developer Portal. You get the files that need it and the link to the right page. Enable it, save, and the command goes on by itself.

    ```text
    ⚠ Your files need an option that is not enabled for your bot:
      - Message Content Intent, needed by src/events/ping.ts
      Enable it under "Privileged Gateway Intents", then save:
      https://discord.com/developers/applications/123456789012345678/bot
      Waiting for you to enable it...
    ✓ Privileged intents enabled
    ```

    The three options and which files need them are in [Your Discord application](/setup/discord-application#privileged-intents).
  </Accordion>
</AccordionGroup>

<Info>
  The command only waits when it runs in a terminal. Started by another program, the same two messages are errors (`✗`) and the command stops with exit code 1.
</Info>

## Reload on save

Save a file and your bot uses the new version, without disconnecting:

```text
↻ Reloaded in 12 ms, 1 command, 2 events loaded
```

Every file under `src/` is watched: your [commands](/commands), your [events](/events) and the files they import. A new file or a new folder is picked up as soon as it is saved, and several files saved at once are one reload. A file saved while the command was starting is not lost: it is reloaded right after.

A file with a mistake never stops your bot. The error is shown with the file and the line, and **the last version that worked keeps running** until you fix it:

```text
✗ src/events/ping.ts:4 Expression expected
⚠ Reloaded with an error: that file keeps running its last working version
```

With several broken files, the message counts them: `⚠ Reloaded with 2 errors: those files keep running their last working version`. A file that never worked is left out until it does.

<Info>
  Reloading starts your files again from scratch: a variable kept in a file (a counter, a list...) goes back to its first value on every save. Packages from `node_modules` are not reloaded.
</Info>

### When your files need more from Discord

The intents are given to Discord when the bot connects. When a file you save needs one the connection does not have (a new event folder, a file that now listens to private messages), the bot reconnects by itself:

```text
↻ Your files now need more from Discord (GUILD_MEMBERS): reconnecting...
✓ Reconnected, 3 events loaded
```

If that intent is privileged and not enabled yet, you get the same message and the same wait as before connecting. The `ready` event runs once per start, not when the bot reconnects.

## Your commands on your test server

Your commands are registered on your test server only, where they show up at once. Discord is told again only when something people see changed (a name, a description, an option, a translation): changing what a command *does* costs no request, and neither does starting the bot again.

```text
✓ Commands updated on My Server
```

On a reload, the line is `↻ Commands updated on Discord`. When Discord refuses what your files declare, the bot keeps running with the commands Discord already has:

```text
✗ Discord refused the commands of your project: Discord refused PUT /applications/{application.id}/guilds/{guild.id}/commands: Invalid Form Body (50035)
    [0].name: Command name is invalid
```

A command that production already shows for everyone, exactly as your file declares it, is not added a second time. While you are changing one, your test server shows it twice and the command tells you once:

```text
ℹ /poll is not the same here as in production, so My Server shows it twice: yours, and the one everyone has. It is shown once again when production runs your version.
```

A dev application never shows that: see [A second bot for development](/run/start#a-second-bot-for-development).

## Only your test server

In dev, your bot only sees the server of `DEV_GUILD_ID`. What happens in the other servers it is in, and in private messages, is ignored, and the intents that only serve private messages are not asked for. That is for [`chapterjs start`](/run/start), which can run the same bot for everyone at the same time.

What only works in private messages can't be tried in dev, and `chapterjs dev` names the file once:

```text
ℹ src/commands/settings.ts /settings only works in private messages, and chapterjs dev only runs your bot in My Server. Try it with chapterjs start.
ℹ src/events/inbox.ts this messageCreate file only works in private messages, and chapterjs dev only runs your bot in My Server. Try it with chapterjs start.
```

## The types of your project

When it starts, `chapterjs dev` writes the types of your project in the `.chapterjs/` folder: this is how `event` knows, in each [event folder](/events), what its function receives. The folder is ignored by git and safe to delete.

[`chapterjs sync`](/reference/cli#chapterjs-sync) writes them without starting the bot. Projects created with `create chapter` run it after each install, so your editor knows the types right away.

To check the types of your whole project from a terminal, use the `typecheck` script of your project:

<CodeGroup>
```bash pnpm
pnpm typecheck
```

```bash npm
npm run typecheck
```

```bash yarn
yarn typecheck
```

```bash bun
bun typecheck
```
</CodeGroup>

<Warning>
  It runs `tsc -b`. A plain `tsc` checks nothing in a ChapterJS project: your files are checked by the projects of `.chapterjs/`, which only `tsc -b` and your editor follow.
</Warning>

## While the bot runs

The connection to Discord is kept alive by the framework. When it drops, the bot reconnects by itself and your files keep running:

```text
⚠ Connection to Discord lost, reconnecting...
↻ Reconnected to Discord
```

An error in one of your functions is shown with the file and the line, and stops nothing else: see [when your function fails](/commands/answering#when-your-function-fails). The bot also looks after its own memory: see [Memory](/memory).

## A new version of ChapterJS

Once the bot is online, `chapterjs dev` tells you when a newer version of the package is out, with the command that installs it, written for the package manager of your project:

```text
ℹ A new version of chapterjs is out: 0.3.0 (you have 0.2.0). To update, run:
  pnpm update chapterjs --latest
  What changed: https://www.chapterjs.org/changelog
```

npm is asked at most once a day, after the bot is online, and never holds it: without internet, the line does not appear. Nothing is installed for you: run the command when you want, then start `chapterjs dev` again.

## Stopping

Press `Ctrl+C`. The bot disconnects properly and goes offline at once:

```text
✓ Disconnected
```

A second `Ctrl+C` stops the process without waiting; Discord then keeps the bot shown online until it notices the connection is gone.
