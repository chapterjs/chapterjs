<Note>
  Comment écrire un fichier d’événement est dans [Événements](/fr/events) ; les événements sur les messages et leurs options dans [Messages](/fr/events/messages) ; `event()` et ses types dans [event()](/fr/reference/event).
</Note>

Un événement est un dossier de `src/events/`. Chaque section ci-dessous est un dossier : quand ses fichiers tournent, les intents dont Discord a besoin pour lui (déduits de vos fichiers, jamais écrits par vous), ses options, ce dont le bot se souvient pour lui au-delà de [la valeur par défaut](/fr/memory), et ce que reçoit votre fonction.

Les intents sont nommés comme les affiche `chapterjs dev`. Deux sont privilégiés, à activer dans le [Developer Portal](/fr/setup/discord-application) : `GUILD_MEMBERS` est le Server Members Intent, `MESSAGE_CONTENT` le Message Content Intent.

## ready

| | |
| --- | --- |
| Quand | Le bot est connecté et connaît chaque serveur où il se trouve. Une fois par démarrage, jamais à nouveau lors d’un rechargement. |
| Intents | Aucun |
| Options | Aucune |
| Mémoire | Par défaut |

Chaque événement reçoit aussi `t`, dans la langue du serveur où il s’est produit, quand le projet a une langue dans `src/messages/` : voir [`TranslationContext`](/fr/reference/messages#translationcontext).

<ResponseField name="user" type="User" required>
  Le bot lui-même.
</ResponseField>
<ResponseField name="guilds" type="ReadonlyMap<Snowflake, Guild>" required>
  Les serveurs où se trouve le bot.
</ResponseField>

## messageCreate

| | |
| --- | --- |
| Quand | Un message a été envoyé, sur un serveur ou en privé. Par défaut, seulement par une personne, sur un serveur. |
| Intents | `MESSAGE_CONTENT` (privilégié), plus `GUILD_MESSAGES` pour un fichier qui écoute sur les serveurs et `DIRECT_MESSAGES` pour un fichier qui écoute en messages privés |
| Options | `bots`, `where` ([MessageEventOptions](/fr/reference/event#messageeventoptions)) |
| Mémoire | Par défaut |

<ResponseField name="message" type="MemberMessage" required>
  Le message envoyé. Le type suit les options du fichier : `MemberMessage` par défaut, `GuildMessage` avec `bots: true`, `DmMessage` avec `where: 'dm'`, `MemberMessage | PrivateMessage` avec `where: 'both'` (`GuildMessage | PrivateMessage` avec les deux options). Les quatre sont dans [Message](/fr/reference/message#types).
</ResponseField>

## messageDelete

| | |
| --- | --- |
| Quand | Un message a été supprimé. Par défaut, seulement sur un serveur. |
| Intents | `GUILD_MESSAGES` pour un fichier qui écoute sur les serveurs, `DIRECT_MESSAGES` pour un fichier qui écoute en messages privés |
| Options | `where` ([WhereEventOptions](/fr/reference/event#whereeventoptions)) |
| Mémoire | Par défaut : aucun message, donc `message` est `null` aujourd’hui |

Ce que reçoit un fichier sans `where` :

<ResponseField name="messageId" type="Snowflake" required>
  L’identifiant du message supprimé.
</ResponseField>
<ResponseField name="channelId" type="Snowflake" required>
  L’identifiant du salon où était le message.
</ResponseField>
<ResponseField name="guildId" type="Snowflake" required>
  L’identifiant du serveur.
</ResponseField>
<ResponseField name="guild" type="Guild" required>
  Le serveur où était le message.
</ResponseField>
<ResponseField name="channel" type="GuildTextBasedChannel" required>
  Le salon où était le message.
</ResponseField>
<ResponseField name="message" type="GuildMessage | null" required>
  Le message tel qu’il était, quand le bot s’en souvenait.
</ResponseField>

Avec `where: 'dm'`, `guildId` et `guild` n’existent pas, `channel` est un `DMChannel | null` (la conversation privée, quand le bot la connaît) et `message` un `DmMessage | null`. Avec `where: 'both'`, un message privé arrive avec `guildId: null`, `guild: null`, `channel: DMChannel | null` et `message: PrivateMessage | null`, donc `guild` distingue les deux.
