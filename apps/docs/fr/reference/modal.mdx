`modal()` déclare un formulaire, depuis n’importe quel fichier de `src/` ; le nom de son export est son identifiant. Elle prend un objet, `ModalConfig`, et type `fields` dans `run` d’après lui.

```ts src/components/feedback.ts
import { modal } from 'chapterjs';

export default modal({
  title: 'Avis',
  fields: {
    text: { type: 'text', label: 'Qu’en pensez-vous ?', style: 'paragraph' },
  },
  async run({ interaction, fields }) {
    await interaction.reply({ content: `Merci ! Vous avez écrit : ${fields.text}`, ephemeral: true });
  },
});
```

<Note>
  Comment écrire un formulaire, l’ouvrir et lire ce qui a été rempli est dans le [guide](/fr/components/modals). Cette page liste ce qui existe. L’endroit (`where`, `PlaceOf`...) est sur la [page de button()](/fr/reference/button#l’endroit).
</Note>

## modal()

```ts
modal<Fields extends ModalFields, Data extends DataShape = {}, Where extends ComponentWhere = 'guild'>(config: ModalConfig<Fields, Data, Where>): ModalDeclaration<Fields, Data>
```

Déclare un formulaire. Exportez le résultat depuis n’importe quel fichier de `src/` : le nom de l’export est ce qui distingue le formulaire, donc vous n’écrivez jamais d’identifiant.

### ModalDeclaration

Ce que renvoie `modal()` : une déclaration que le framework trouve dans les exports d’un fichier. Importez-le là où quelqu’un utilise une commande ou un composant, et ouvrez-le : `interaction.showModal(report({ userId }))`, ou `interaction.showModal(feedback)` pour un formulaire sans données.

```ts
type ModalDeclaration<Fields extends ModalFields = ModalFields, Data extends DataShape = {}> = { readonly config: unknown } &
  ({} extends Data
    ? ((options?: ModalInstanceOptions<Fields>) => ModalComponent) & ModalComponent
    : {} extends DataInputOf<Data>
      ? ((data?: DataInputOf<Data>, options?: ModalInstanceOptions<Fields>) => ModalComponent) & ModalComponent
      : (data: DataInputOf<Data>, options?: ModalInstanceOptions<Fields>) => ModalComponent)
```

<ResponseField name="config" type="unknown">
  Ce que le fichier a donné à `modal()`, pas encore vérifié.
</ResponseField>

### ModalInstanceOptions

Ce avec quoi un formulaire est ouvert : ses données, et ce que contiennent certains champs.

<ResponseField name="values" type="ModalPrefill<Fields>">
  Ce que contiennent certains champs quand le formulaire s’ouvre.
</ResponseField>

### ModalPrefill

Ce qu’un formulaire peut contenir quand il s’ouvre : une valeur pour certains de ses champs. Un `string` pour un `text`, une liste de valeurs pour un `select` ou des `checkboxes`, une valeur pour un `radio`, un `boolean` pour une `checkbox`. Les autres sortes de champs ne peuvent pas être pré-remplies.

## ModalConfig

Ce qu’un fichier de formulaire donne à `modal()`.

<ResponseField name="title" type="DynamicText" required>
  Le titre du formulaire (45 caractères au plus) : écrit tel quel, ou une fonction de `t` et des données, lancée à l’ouverture du formulaire. Voir [DynamicText](/fr/reference/messages#dynamictext).
</ResponseField>

<ResponseField name="fields" type="ModalFields" required>
  Les champs, par nom (1 à 5). `run` les reçoit sous les mêmes noms.
</ResponseField>

<ResponseField name="run" type="(context: ModalContext<Fields, Data, Where>) => unknown" required>
  Ce qu’il faut faire quand quelqu’un envoie le formulaire.
</ResponseField>

<ResponseField name="data" type="DataShape">
  Ce que le formulaire transporte depuis le code qui l’ouvre jusqu’au code qui tourne à l’envoi : un nom et une sorte pour chaque valeur. Donné à l’ouverture du formulaire, reçu typé dans `run`.
</ResponseField>

<ResponseField name="where" type="ComponentWhere">
  D’où le formulaire peut être envoyé : `'guild'` (serveurs, par défaut), `'dm'` (messages privés avec le bot) ou `'both'`. Ce que reçoit `run` suit.
</ResponseField>

<ResponseField name="ephemeral" type="boolean">
  Rendre les réponses du formulaire visibles seulement par qui l’a envoyé. Quand un composant d’un message que seule la personne voit l’a ouvert, elles le sont déjà.
</ResponseField>

[Documentation de Discord](https://docs.discord.com/developers/interactions/receiving-and-responding#interaction-response-object-modal)

## Les champs

### ModalFields

```ts
type ModalFields = Readonly<Record<string, ModalField>>
```

Les champs d’un formulaire, par nom (5 au plus). Un nom est la façon dont votre code lit le champ (`fields.reason`) : lettres, chiffres et `_`.

### ModalField

```ts
type ModalField = TextField | SelectField | EntityField | FilesField | RadioField | CheckboxesField | CheckboxField | NoteField
```

Un champ d’un formulaire. Chaque champ sauf une note a :

<ResponseField name="label" type="DynamicText" required>
  Le nom du champ, au-dessus de lui (45 caractères au plus) : écrit tel quel, ou une fonction de `t` et des données, lancée à l’ouverture du formulaire.
</ResponseField>

<ResponseField name="description" type="DynamicText">
  Un texte d’aide sous l’étiquette (100 caractères au plus) : un texte, ou une fonction de `t` et des données.
</ResponseField>

[Documentation de Discord](https://docs.discord.com/developers/components/reference#label)

### TextField

Un texte que la personne tape.

<ResponseField name="type" type="'text'" required>
  La sorte de champ : un texte.
</ResponseField>

<ResponseField name="style" type="'short' | 'paragraph'">
  Une ligne (`'short'`, par défaut) ou plusieurs (`'paragraph'`).
</ResponseField>

<ResponseField name="placeholder" type="DynamicText">
  Le texte affiché tant que le champ est vide (100 caractères au plus) : un texte, ou une fonction de `t` et des données.
</ResponseField>

<ResponseField name="required" type="boolean">
  Si la personne doit le remplir. `true` par défaut.
</ResponseField>

<ResponseField name="minLength" type="number">
  Le texte le plus court accepté, en caractères (0 à 4000).
</ResponseField>

<ResponseField name="maxLength" type="number">
  Le texte le plus long accepté, en caractères (1 à 4000).
</ResponseField>

<ResponseField name="value" type="string">
  Ce que contient le champ quand le formulaire s’ouvre (4000 caractères au plus).
</ResponseField>

[Documentation de Discord](https://docs.discord.com/developers/components/reference#text-input)

<ResponseField name="options" type="SelectOptions" required>

<ResponseField name="placeholder" type="DynamicText">

<ResponseField name="min" type="number">

## Ce que reçoit run

### ModalContext

Ce que reçoit `run` quand le formulaire est envoyé : l’endroit tel que le donne [PlaceOf](/fr/reference/button#placeof) avec une [ModalInteraction](/fr/reference/interaction#modalinteraction), et :

<ResponseField name="user" type="User" required>
  Qui a envoyé le formulaire.
</ResponseField>

<ResponseField name="fields" type="FieldValuesOf<Fields>" required>
  Ce que la personne a rempli.
</ResponseField>

<ResponseField name="data" type="DataValuesOf<Data>" required>
  Ce que transporte le formulaire, tel que déclaré dans `data`.
</ResponseField>

<ResponseField name="message" type="Message | null" required>
  Le message dont le bouton ou le menu a ouvert le formulaire ; `null` quand c’est une commande.
</ResponseField>

### FieldValuesOf

```ts
type FieldValuesOf<Fields extends ModalFields> = { [Name in keyof Fields]: FieldValue<Fields[Name]> }
```

Ce que la personne a rempli, typé champ par champ. Les notes n’y sont pas.

### FieldValue

Ce que reçoit `run` pour un champ, d’après sa déclaration :

| Champ | `FieldValue` |
| --- | --- |
| `TextField` | `string`, ou `string \| undefined` avec `required: false` |
| `SelectField` | `OptionValue<Options>[]` |
| `EntityField` | `User[]`, `Role[]`, `(User \| Role)[]` ou `Channel[]` |
| `FilesField` | [`Attachment`](/fr/reference/data#attachment)`[]` |
| `RadioField` | `OptionValue<Options>`, ou `\| undefined` avec `required: false` |
| `CheckboxesField` | `OptionValue<Options>[]` |
| `CheckboxField` | `boolean` |

[Documentation de Discord](https://docs.discord.com/developers/interactions/receiving-and-responding#interaction-object-modal-submit-data-structure)
