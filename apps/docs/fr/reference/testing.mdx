`scenario()` déclare un test de votre bot, depuis un fichier `*.test.ts` de `src/`, et `chapterjs test` le lance contre un Discord en mémoire. Tout ce qui est sur cette page s’importe depuis `chapterjs/test`.

```ts src/checks/hello.test.ts
import { scenario } from 'chapterjs/test';
import { hello } from './hello';

export default scenario('hello salue', async bot => {
  const reply = await bot.use(hello, { who: bot.member('alice') });
  reply.says('Bonjour alice').isPublic();
});
```

```ts src/checks/hello.ts
import { command } from 'chapterjs';

export const hello = command({
  name: 'hello',
  description: 'Dit bonjour',
  options: { who: { type: 'user', description: 'Qui', required: true } },
  async run({ interaction, options }) {
    await interaction.reply(`Bonjour ${options.who.username} !`);
  },
});
```

<Note>
  Comment tester un bot, ce qui est vérifié sans scénario et ce qu’a le serveur de test est dans le [guide](/fr/testing). Cette page liste ce qui existe.
</Note>

## scenario()

```ts
scenario(label: string, run: (bot: TestBot) => unknown): ScenarioDeclaration
```

Déclare un test de votre bot. Exportez le résultat depuis un fichier `*.test.ts` de `src/` : `chapterjs test` le lance contre un Discord en mémoire, où le bot est dans un serveur avec quelques personnes.

`bot` est le bot dans son serveur de test : `bot.use()` lance une commande, `bot.click()` appuie sur un bouton, `bot.say()` envoie un message en tant que quelqu’un, et ce qui revient dit ce que le bot a répondu.

Un fichier peut exporter plusieurs scénarios, dans une liste aussi. Le libellé est ce que montre le rapport : il ne peut pas être vide, et 120 caractères est le maximum.

### ScenarioDeclaration

Ce que renvoie `scenario()` : une déclaration que le lanceur trouve dans les exports d’un fichier.

<ResponseField name="config" type="{ label: string; run: (bot: TestBot) => unknown }">
  Ce que le fichier a donné à `scenario()`, pas encore vérifié.
</ResponseField>

## TestBot

Le bot du projet, qui tourne dans un Discord en mémoire : un serveur, quelques personnes, et tout ce que fait le bot gardé là où le test peut le lire.

<ResponseField name="guild" type="{ id: string; name: string }" required>
  Le serveur de test.
</ResponseField>

<ResponseField name="me" type="TestMember" required>
  Le bot lui-même, en tant que membre du serveur.
</ResponseField>

<ResponseField name="owner" type="TestMember" required>
  Le propriétaire du serveur.
</ResponseField>

<ResponseField name="someone" type="TestMember" required>
  Une personne sans droit particulier : qui fait les choses quand personne n’est nommé.
</ResponseField>

<ResponseField name="requests" type="{ method: string; path: string; body: unknown }[]" required>
  Chaque requête que le bot a envoyée à Discord jusqu’ici.
</ResponseField>

### member()

```ts
member(name: string, options?: TestMemberOptions): TestMember
```

Une personne du serveur, créée la première fois que le nom est donné. Les options ne comptent que la première fois.

### role()

```ts
role(name: string, options?: TestRoleOptions): TestRole
```

Un rôle du serveur, créé la première fois que le nom est donné.

### channel()

```ts
channel(name: string, options?: TestChannelOptions): TestChannel
```

Un salon du serveur, créé la première fois que le nom est donné. `#general` existe.

### use()

```ts
use(command: CommandDeclaration, options?: OptionInputsOf<Options>, where?: TestWhere): Promise<TestReply>
use(command: MenuDeclaration, target: TestMenuTarget, where?: TestWhere): Promise<TestReply>
```

Utilise une commande, comme une personne le ferait : une commande slash avec ses options, ou une commande de menu sur ce sur quoi elle s’utilise (`{ on: message }`, `{ on: member }` ; un menu de message s’utilise dans le salon de son message). Se résout une fois que le bot a répondu.

`options` est typé depuis les options de la commande (`OptionInputsOf`) : un texte, un nombre, `true` ou `false`, l’un des `choices`, un `TestMember` pour une option `user`, un `TestRole` pour une option `role`, un `TestChannel` pour une option `channel`, un `TestFile` pour une option `attachment`. Il peut être omis quand la commande n’en exige aucune. Ce que Discord ne laisserait pas une personne envoyer (une option obligatoire manquante, un nombre hors de sa plage, un texte trop long, une valeur qui n’est pas un des choix) fait échouer le scénario avant que le bot n’en entende parler.

### click()

```ts
click(button: ButtonTarget, where?: TestWhere): Promise<TestReply>
```

Clique sur un bouton. Se résout une fois que le bot a répondu. Un bouton trouvé sur un message (`reply.button('Confirmer')`) est cliqué sur ce message, comme le ferait une personne.

### select()

```ts
select(menu: SelectTarget, values: readonly SelectInput[], where?: TestWhere): Promise<TestReply>
```

Choisit des valeurs dans un menu déroulant. Se résout une fois que le bot a répondu. `values` sont des textes pour un menu de textes (les valeurs de ses options), des personnes, des rôles ou des salons pour les autres ; les `min` et `max` du menu sont appliqués.

### submit()

```ts
submit(form: FormTarget<Fields>, fields?: FieldInputsOf<Fields>, where?: TestWhere): Promise<TestReply>
```

Remplit et envoie un formulaire. Se résout une fois que le bot a répondu. `fields` est typé depuis les champs du formulaire (`FieldInputsOf`) : un texte pour un champ `text`, une liste de valeurs d’options pour un `select` ou `checkboxes`, une valeur d’option pour un `radio`, `true` ou `false` pour un `checkbox`, des personnes, rôles ou salons pour les autres, des fichiers pour un champ `files`. Un champ omis reste vide ; un champ obligatoire omis fait échouer le scénario, comme l’application Discord refuserait d’envoyer le formulaire.

### suggest()

```ts
suggest(command: CommandDeclaration, option: string, typed: string, where?: TestWhere): Promise<TestSuggestion[]>
```

Tape dans une option avec suggestions, et récupère ce que le bot suggère.

### say()

```ts
say(content: string, where?: TestWhere): Promise<TestMessage>
```

Envoie un message en tant que quelqu’un. Se résout une fois que le bot l’a traité.

### react()

```ts
react(message: TestMessage, emoji: string, where?: { by?: TestMember }): Promise<void>
```

Réagit à un message en tant que quelqu’un. Se résout une fois que le bot l’a traité.

### join()

```ts
join(member: string | TestMember, options?: TestMemberOptions): Promise<TestMember>
```

Fait rejoindre le serveur à quelqu’un. Se résout une fois que le bot l’a traité.

### leave()

```ts
leave(member: TestMember): Promise<void>
```

Fait quitter le serveur à quelqu’un. Se résout une fois que le bot l’a traité.

### run()

```ts
run(task: TaskDeclaration, at?: Date): Promise<void>
```

Lance une tâche maintenant, comme si son heure était venue. Se résout une fois qu’elle a fini.

### settle()

```ts
settle(): Promise<void>
```

Attend que tout ce que le bot a commencé soit terminé.

Tout sauf ce qui attend que le test agisse : une fonction qui attend un message, un clic ou une réaction (`waitForMessage()`…) reste en attente, et `use()`, `say()`, `click()`… se résolvent pendant ce temps.

### endWaits()

```ts
endWaits(): Promise<void>
```

Termine tout ce qu’attend le bot (`waitForMessage()`, `waitForClick()`…) comme si son temps était écoulé : le temps ne passe pas dans le serveur de test. Se résout une fois que le bot l’a traité.

## TestWhere

Qui fait quelque chose, et où.

</ResponseField>

</ResponseField>

<ResponseField name="embeds" type="Embed[]" required>

  Ses boutons, dans l’ordre.
</ResponseField>

<ResponseField name="menus" type="TestMenu[]" required>
  Ses menus déroulants, dans l’ordre.
</ResponseField>

<ResponseField name="followUps" type="TestMessage[]" required>
  Les messages envoyés après la première réponse, dans l’ordre.
</ResponseField>

<ResponseField name="form" type="TestForm | null" required>
  Le formulaire que le bot a ouvert, ou `null`.

### opensForm()

## TestAssertions

Ce qui se vérifie d’un message ou d’une réponse. Chaque vérification lance une `TestFailure` avec une phrase en clair quand elle échoue, et renvoie ce qu’elle a vérifié sinon, pour enchaîner.

### says()

```ts

```

Vérifie que le texte contient `text` (ou lui correspond).

### saysExactly()

```ts

```

Vérifie que le texte est exactement `text`.

### isEphemeral()

```ts
isEphemeral(): Self
```

Vérifie que seule la personne qui a demandé le voit.

### isPublic()

```ts
isPublic(): Self
```

Vérifie que tout le monde le voit.

### hasButton()

```ts

```

Vérifie qu’il y a un bouton avec ce libellé.

### hasEmbed()


Vérifie qu’il y a un embed, avec ce titre quand il est donné.

### hasNoEmbed()

### hasNoComponent()

## Types

- `OptionInputsOf<Options>` : les options d’une commande telles qu’un test les remplit. Une option obligatoire ne peut pas être omise.
- `FieldInputsOf<Fields>` : les champs d’un formulaire tels qu’un test les remplit : un champ omis reste vide.
- `SelectInput` : ce qu’un test choisit dans un menu : des textes, ou des personnes, rôles et salons.
- `TestMenuTarget<Type>` : ce sur quoi s’utilise une commande de menu dans un test : `{ on }`, un `TestMember` pour un menu `'user'`, un `TestMessage` pour un menu `'message'`.
- `ButtonTarget` : un bouton, tel qu’un test le nomme : la déclaration, une instance, ou un bouton trouvé sur un message (`reply.button('Confirmer')`).
- `SelectTarget` : un menu, de la même façon (`reply.menu()`).
- `FormTarget<Fields>` : un formulaire, de la même façon (`reply.form`).
- `TestChannelType` : `'text' | 'announcement' | 'voice' | 'category' | 'forum'`.
- `TestFailure` : une attente d’un test que le bot n’a pas satisfaite. Ce que lance chaque vérification, avec une phrase en clair : le rapport l’affiche avec la ligne du scénario.
