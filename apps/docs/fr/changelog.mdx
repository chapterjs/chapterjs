`chapterjs`, `create-chapter` et `create-chapterjs` ont toujours le même numéro de version. Seul `chapterjs` vit dans votre projet ; `chapterjs dev` vous prévient quand un plus récent est sorti. Pour le mettre à jour :

<CodeGroup>

```bash pnpm
pnpm update chapterjs --latest
```

```bash npm
npm install chapterjs@latest
```

```bash yarn
yarn add chapterjs@latest
```

```bash bun
bun add chapterjs@latest
```

</CodeGroup>

<Update label="0.2.3" description="Stockage, cinq modèles, et un nouveau projet à la version de create chapter, exactement">

Votre bot peut garder ce qu’il apprend : `export const warnings = store<Warning[]>({ expires: '30d' })` déclare un [store](/fr/storage), par serveur sauf `scope: 'global'`, typé par ce qu’il contient, avec une expiration si vous en voulez une. Dans une commande ou un événement, la clé est à vous et le serveur est connu ; ailleurs, `warnings.in(guild)`. Un fichier JSON par store dans `data/`, écrit pour vous, et partagé par chaque processus d’un gros bot.

`create chapter` propose maintenant cinq [modèles](/fr/setup/project-structure#modèles). `default` est un fichier, l’événement `ready`, et le tutoriel part de lui. Les autres sont des bots complets : `tickets` (des tickets de support dans des fils privés), `music` (un lecteur avec une file d’attente et des boutons), `community` (cartes de bienvenue, rôles à choisir, chiffres hebdomadaires) et `moderation` (exclusions temporaires, purge, mode lent, verrouillage, et un journal de chaque action). Les exemples `/ping`, `/hello`, `/play` et de modération de l’ancien modèle ont disparu : ce qu’ils montraient est dans les nouveaux et dans le guide.

`create chapter` écrit aussi la version exacte de `chapterjs` dans votre `package.json` (`"0.2.3"`, sans `^`) : `pnpm create chapter@0.2.3` donne un projet en `chapterjs@0.2.3`, et votre projet ne change de version que quand vous lancez la commande que [`chapterjs dev` vous donne](/fr/run/dev#une-nouvelle-version-de-chapterjs).

</Update>

<Update label="0.2.2" description="Un template par défaut plus léger">

Le projet créé par `create chapter` n’embarque plus l’exemple de modération (`/ban`, `/kick`, `/warn`) : il garde `/ping`, `/hello`, `/play`, les deux événements, la présence et les deux langues.

</Update>

<Update label="0.2.1" description="chapterjs dev vous prévient quand une nouvelle version est sortie">

Une fois le bot en ligne, `chapterjs dev` dit quand une version plus récente de `chapterjs` est publiée, avec la commande qui l’installe, écrite pour le gestionnaire de paquets de votre projet. npm est interrogé au plus une fois par jour, et ne retient jamais le bot. Voir [Une nouvelle version de ChapterJS](/fr/run/dev#une-nouvelle-version-de-chapterjs).

</Update>

<Update label="0.2.0" description="Vos fichiers, votre ordre : le framework lit ce qu’ils exportent">

Plus rien n’est lié à un dossier. Chaque fichier de `src/` est chargé, et ce qu’il exporte de fabriqué avec `command()`, `event()`, `button()`, `select()`, `modal()`, `embed()`, `task()`, `presence()` ou `language()` est ce que le bot fait tourner : un fichier peut déclarer plusieurs choses, et se trouver où vous voulez. Voir [Structure du projet](/fr/setup/project-structure).

- **[Les commandes](/fr/commands)** prennent un `name` : `command({ name: 'ping', ... })`, `'mod ban'` pour une sous-commande. Deux commandes du même nom sont signalées, où qu’elles soient.
- **[Les événements](/fr/events)** prennent un `name` aussi, qui type ce que reçoit `run` : `event({ name: 'memberJoin', run({ member }) { ... } })`. Les options s’écrivent à côté (`bots: true`, `where: 'dm'`), et une faute dans l’un ou l’autre est soulignée.
- **[Les composants](/fr/components)** et **[les tâches](/fr/tasks)** sont nommés par leur export : `export const again = button(...)` est le bouton `again`. Déplacer un fichier ne change rien ; renommer l’export, si, comme renommer le fichier le faisait.
- **[Les langues](/fr/translated-messages)** disent leur `locale` : `language({ locale: 'fr', ... })`, et un deuxième `default: true` est souligné dans les deux fichiers. Une langue peut être déclarée à plusieurs endroits : les textes d’une fonctionnalité vivent à côté d’elle, et `t` les propose tous. Un texte que la langue par défaut n’a pas est pris dans la langue qui l’a, donc un module écrit dans d’autres langues que les vôtres fonctionne quand même.
- `.chapterjs/` est un seul projet TypeScript pour tout `src/`, et ne contient que ce que le projet ajoute : les fichiers de `public/`, les langues et les commandes. Les dossiers entre parenthèses et les fichiers `_` ne servent plus : un dossier n’est qu’un dossier, et un fichier qui ne déclare rien est à vous.

Les types `EventFile`, `CommandFile`, `ButtonFile`, `SelectFile`, `ModalFile`, `EmbedFile`, `TaskFile`, `PresenceFile` et `LanguageFile` s’appellent maintenant `EventDeclaration`, `CommandDeclaration`, `ButtonDeclaration`, `SelectDeclaration`, `ModalDeclaration`, `EmbedDeclaration`, `TaskDeclaration`, `PresenceDeclaration` et `LanguageDeclaration`.

</Update>

<Update label="0.1.4" description="La première version du framework">

Un dossier de fichiers devient un bot Discord.

- **[Commandes](/fr/commands)** : un fichier de `src/commands/` est une commande slash, avec ses options typées, ses choix, l'[autocomplétion](/fr/commands/options#autocomplétion), ses permissions, ses délais entre deux utilisations et ses traductions.
- **[Événements](/fr/events)** : un fichier de `src/events/<event>/` s'exécute quand l'événement arrive. Les intents découlent des fichiers que vous écrivez.
- **[Composants](/fr/components)** : boutons, menus déroulants, formulaires et embeds dans `src/components/`, avec des `data` typées et aucun identifiant à écrire.
- **[Tâches](/fr/tasks)** : ce que le bot fait de lui-même, à intervalle régulier ou à heure fixe.
- **[Voix](/fr/voice)** : le bot rejoint un salon vocal et y joue un fichier de `public/`, un fichier envoyé sur Discord ou un lien, chiffré de bout en bout comme Discord le demande.
- **[Présence](/fr/presence)** : ce que le bot affiche sous son nom, dans `src/presence.ts`.
- **[Messages traduits](/fr/translated-messages)** : un fichier par langue dans `src/messages/`, et `t` parle la langue de ceux qui lisent.
- **[`chapterjs dev`](/fr/run/dev)** : le bot sur un serveur de test, chaque fichier rechargé dès que vous l'enregistrez.
- **[`chapterjs build`](/fr/run/build)** et **[`chapterjs start`](/fr/run/start)** : un seul fichier compilé pour la production, réparti sur plusieurs processus quand le bot est grand.
- **[`create-chapter`](/fr/quickstart)** : un nouveau projet en une commande.
- **[Node.js 24](/fr/quickstart)** ou plus récent : `chapterjs` et `create-chapter` s'arrêtent tout de suite avec une version plus ancienne et disent quoi installer.

</Update>
