## Modèles

`create chapterjs` propose cinq modèles. `default` est présélectionné : un fichier, et le reste de ce site pour le faire grandir. Les autres sont des bots complets : lisez-les une fois le framework connu, ou partez de l’un d’eux.

| Modèle       | Ce que c’est                                                                                                                                                                              |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `default`    | Un événement, `ready`, qui affiche une ligne quand le bot est en ligne. Rien d’autre.                                                                                                     |
| `tickets`    | Des tickets de support dans des fils privés : `/ticket panel` poste un bouton, qui ouvre un formulaire, qui ouvre un fil avec un bouton de fermeture pour le staff ou la personne.        |
| `music`      | Un lecteur de musique en vocal : `/play` avec un fichier ou un lien, une file d’attente par serveur, `/queue`, `/leave`, et des boutons pause, passer et stop sous « Now playing ».        |
| `community`  | Une carte de bienvenue quand quelqu’un arrive, un au revoir quand il part, `/roles` pour choisir ses rôles dans un menu, et une tâche hebdomadaire qui poste les chiffres du serveur.     |
| `moderation` | `/timeout` et `/untimeout`, `/purge`, `/slowmode`, `/lock` et `/unlock`, avec les permissions dont chacune a besoin, et un journal de chaque action de modération dans `#mod-log`.       |

Chaque modèle sauf `default` a ses textes en deux langues (`en-US` et `fr`) et une présence. `community` a besoin du Server Members Intent, pour savoir qui arrive : `chapterjs dev` dit où l’activer.

## `src/` : ce qu’un fichier exporte dit ce qu’il est

ChapterJS ne vous demande jamais d’enregistrer quoi que ce soit. Il charge chaque fichier de `src/`, où qu’il soit et quel que soit son nom, et fait tourner ce que les fichiers **exportent**, fabriqué avec l’une de ses fonctions :

| Déclaré avec                                      | Ce que c’est                                                                                                                                              |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `command({ name, ... })`                          | Une commande slash : `name` est ce que les gens tapent après le `/`. `'ping'` est `/ping`, `'mod ban'` est `/mod ban`                                      |
| `event({ name, ... })`                            | Une réaction à un événement : `name` est l’événement, `'memberJoin'` tourne quand quelqu’un arrive                                                         |
| `button({ ... })`, `select({ ... })`, `modal({ ... })`, `embed({ ... })` | Un bouton, un menu déroulant, un formulaire ou un embed, distingués par **le nom de leur export** : `export const again = button(...)` est le bouton `again` |
| `task({ ... })`                                   | Quelque chose que le bot fait tout seul, régulièrement ou à des heures données, nommé d’après son export                                                  |
| `presence({ ... })`                               | Ce que le bot affiche sous son nom : son statut et ce qu’il fait, déclaré une fois                                                                        |
| `language({ locale, ... })`                       | Une langue du bot : `locale` dit laquelle ; chaque fonction reçoit alors `t`                                                                              |

Tous s’importent du même endroit, et un fichier peut en déclarer autant que vous voulez. Les modèles font les deux : `default` garde un dossier par sorte (`src/events/`), `tickets` met tout ce qui touche aux tickets dans `src/tickets/` : la commande, le formulaire, les boutons et leurs textes. Un fichier qui déclare plusieurs choses ressemble à ceci :

```ts src/moderation/ban.ts
import { button, command, event } from 'chapterjs';

export default command({
  name: 'ban',
  description: 'Bannit un membre',
  options: {
    target: { type: 'user', description: 'Qui bannir', required: true },
  },
  async run({ interaction, options }) {
    await interaction.reply({
      content: `Bannir ${options.target.displayName} ?`,
      components: [confirmBan({ userId: options.target.id })],
    });
  },
});

export const confirmBan = button({
  label: 'Bannir',
  style: 'danger',
  data: { userId: 'string' },
  async run({ interaction, data, guild }) {
    await guild.ban(data.userId, { reason: 'Banni avec /ban' });
    await interaction.update({ content: 'Banni.', components: [] });
  },
});

export const logged = event({
  name: 'banAdd',
  run({ user, guild }) {
    console.log(`${user.username} a été banni de ${guild.name}`);
  },
});
```

Tout fichier qui n’exporte rien de tout ça est à vous : `src/lib/greet.ts`, `src/db/index.ts`, ce que vous voulez. Il est chargé avec les autres, et vos fichiers l’importent comme d’habitude.

<Note>
  Comment écrire chaque sorte de déclaration est dans [Commandes](/fr/commands),
  [Événements](/fr/events), [Boutons](/fr/components) et [Tâches](/fr/tasks).
</Note>

## Les noms

Deux choses se nomment elles-mêmes, parce que Discord les affiche ou parce qu’elles sont la chose même : une commande (`name: 'ping'`) et un événement (`name: 'memberJoin'`). Tout le reste est nommé par son export : `export const again = button(...)` est le bouton `again`, `export const report = task(...)` la tâche `report`. Un export par défaut prend le nom de son fichier : `export default button(...)` dans `src/again.ts` est `again` aussi.

Discord renvoie le nom d’un bouton à chaque clic, donc renommer l’export d’un bouton casse les boutons déjà sur Discord (ils répondent « This button is not available any more. ») ; déplacer le fichier ne change rien.

<Warning>
  Deux choses ne peuvent pas porter le même nom : deux commandes nommées
  `ping`, ou deux boutons exportés sous `confirm`. La seconde est signalée
  avec les deux fichiers et laissée de côté.
</Warning>

## Imports

Vos fichiers sont du TypeScript, exécuté directement par Node. Un import relatif n’a pas besoin d’extension, et un dossier avec un fichier `index` fonctionne aussi :

<CodeGroup>
```ts src/commands/hello.ts
import { command } from 'chapterjs';
import { greet } from '../lib/greet'; // src/lib/greet.ts
import { db } from '../db'; // src/db/index.ts

export default command({
  name: 'hello',
  description: 'Dit bonjour',
  async run({ interaction, user }) {
    db.visits += 1;
    await interaction.reply(greet(user.displayName));
  },
});
```

```ts src/lib/greet.ts
export function greet(name: string): string {
  return `Bonjour ${name} !`;
}
```

```ts src/db/index.ts
export const db = { visits: 0 };
```

</CodeGroup>

Écrire l’extension fonctionne aussi : `'../lib/greet.ts'`.

Les paquets de `node_modules` s’importent comme d’habitude. Chaque fichier de `src/` est surveillé : dans [`chapterjs dev`](/fr/run/dev), enregistrer `src/lib/greet.ts` recharge chaque fichier qui l’utilise. Un test à côté de votre code (`greet.test.ts`, `greet.spec.ts`) est laissé à votre lanceur de tests, et jamais chargé par le bot.

## `public/` : les fichiers que votre bot envoie

Images, documents, sons : mettez-les dans `public/`, dans les dossiers que vous voulez, et envoyez-en un avec `asset('photos/monday.png')` dans les `files` d’un message. Votre éditeur liste les fichiers du dossier pendant que vous tapez, et `chapterjs dev` garde cette liste à jour pendant que vous ajoutez des fichiers. Un fichier est lu quand le message est envoyé. Voir [Fichiers](/fr/messages#fichiers). Un son de `public/` se joue dans un salon vocal de la même façon, avec `voice.play(asset('intro.ogg'))` : voir [Jouer en vocal](/fr/voice).

## `.chapterjs/` : généré, ignoré, supprimable sans risque

Ce dossier est écrit par ChapterJS, et git l’ignore. Il contient :

|          | Ce que c’est                                                                                                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `types/` | Ce que votre projet ajoute aux types de `chapterjs` : les fichiers de `public/` que `asset()` propose, vos langues, qui typent `t`, et vos commandes. Votre éditeur le lit.                   |
| `cache/` | Ce qui a été enregistré sur Discord la dernière fois, pour que redémarrer votre bot ne coûte aucune requête.                                                                                 |
| `build/` | Votre bot compilé, écrit par [`chapterjs build`](/fr/run/build).                                                                                                                             |

Il est écrit quand vous installez votre projet (`postinstall` lance `chapterjs sync`) et à chaque démarrage de `chapterjs dev` ou `chapterjs build`. Si votre éditeur ne connaît pas les fichiers de `public/` ou vos textes, lancez `chapterjs sync` : voir la [référence du CLI](/fr/reference/cli#chapterjs-sync).

## `.env`

Deux valeurs, lues par [`chapterjs dev`](/fr/run/dev) ; [`chapterjs start`](/fr/run/start) n’a besoin que de la première :

```bash .env
BOT_TOKEN=
DEV_GUILD_ID=
```

Où les trouver est dans [Votre application Discord](/fr/setup/discord-application). Le vrai environnement l’emporte sur le fichier : chez un hébergeur, vous donnez `BOT_TOKEN` dans ses réglages et n’envoyez aucun `.env`.

<Warning>
  Votre token est un mot de passe : ne le partagez jamais, et ne committez
  jamais `.env`. Les projets créés avec `create chapterjs` l’ignorent déjà dans
  git.
</Warning>

## `package.json`

Les scripts de votre projet lancent le [CLI](/fr/reference/cli) :

| Script        | Lance             | Quand                                                           |
| ------------- | ----------------- | --------------------------------------------------------------- |
| `dev`         | `chapterjs dev`   | Pendant que vous écrivez votre bot                              |
| `build`       | `chapterjs build` | Avant de le mettre en ligne                                     |
| `start`       | `chapterjs start` | Sur la machine qui l’héberge                                    |
| `typecheck`   | `tsc -b`          | Pour vérifier les types de tout le projet depuis un terminal    |
| `postinstall` | `chapterjs sync`  | Tout seul, après chaque installation                            |

`chapterjs` est la seule dépendance de votre bot, à la version exacte qu’avait `create chapterjs` (`"chapterjs": "0.2.3"`, sans `^`) : votre projet ne change de version que quand vous lancez la commande que [`chapterjs dev` vous donne](/fr/run/dev#une-nouvelle-version-de-chapterjs). TypeScript et `@types/node` sont des dépendances de développement : elles vérifient votre code, et ne servent pas à le faire tourner.

## `tsconfig.json`

Il ne contient que des options du compilateur et une référence vers `./.chapterjs`, qui est là où se trouve le vrai projet : chaque fichier de `src/`, plus ce que le framework écrit sur votre projet. Gardez-le ainsi.

<Warning>
  Un simple `tsc` ne vérifie rien dans un projet ChapterJS. Utilisez le script
  `typecheck`, qui lance `tsc -b` : c’est ce que suit votre éditeur aussi.
</Warning>

## Avec pnpm : un fichier de plus

pnpm refuse d’installer un projet qui a esbuild quelque part dans ses dépendances (ici, à travers `chapterjs`) tant qu’on ne lui a pas dit si le script d’installation d’esbuild peut tourner. Il ne peut pas, et esbuild n’en a pas besoin. `create chapterjs` écrit la réponse pour vous ; dans un projet créé autrement, créez-le à côté de `package.json` :

```yaml pnpm-workspace.yaml
allowBuilds:
  esbuild: false
ignoredBuiltDependencies:
  - esbuild
```
