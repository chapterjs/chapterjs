## The one rule: where a file is says what it is

Everything your bot does lives in `src/`. ChapterJS never asks you to register anything: a file is a command, a reaction to an event or a button **because of the folder it is in**, the way a page of a website is at the address of its file. Open `src/commands/ping.ts`:

```ts src/commands/ping.ts
import { command } from 'chapterjs';

export default command({
  description: 'Replies with Pong!',
  async run({ interaction }) {
    await interaction.reply('Pong!');
  },
});
```

Nothing in this file says "this is the `/ping` command". The name comes from the file name, `ping.ts`, and the fact that it is a command comes from the folder, `src/commands/`. The file only says what the command _does_. Rename the file to `hello.ts`, and the command becomes `/hello`, with nothing else to change.

That is the rule for every folder the framework reads:

| Folder                                                      | A file in it is                                                                                  | It exports                                                           |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| `src/commands/`                                             | A slash command, named after its path: `ping.ts` is `/ping`, `mod/ban.ts` is `/mod ban`          | `command({ ... })`                                                   |
| `src/events/<event>/`                                       | A reaction to the event named by the folder: every file of `memberJoin/` runs when someone joins | `event(({ ... }) => { ... })`                                        |
| `src/components/buttons/`, `selects/`, `modals/`, `embeds/` | A button, a select menu, a form or an embed, told apart by its path                              | `button({ ... })`, `select({ ... })`, `modal({ ... })`, `embed(...)` |
| `src/tasks/`                                                | Something the bot does by itself, every so often or at given times                               | `task({ ... })`                                                      |
| `src/messages/`                                             | One language of the bot, named after it: `fr.ts` is French                                       | `language({ ... })`                                                  |
| `src/presence.ts`                                           | The one file that says what the bot shows under its name                                         | `presence({ ... })`                                                  |

Every other folder of `src/` is yours: `src/lib/`, `src/db/`, anything. The framework only reads the folders above, and your files import the rest as usual.

Why this design? Because the alternative, a list somewhere that says "the `/ping` command is in this file, the welcome event is in that one", is a list you have to keep in sync with your files by hand. Here, there is no list. Adding a command is adding a file; removing one is deleting it.

## The same import everywhere

Every file starts with `import { command } from 'chapterjs'`, or `event`, `button`... All of them come from the same package, `chapterjs`. There is nothing else to import: no client, no configuration, no file of the framework. And in each folder, the function knows what to expect: `event` in `src/events/memberJoin/` gives your function a member, and `event` in `src/events/messageCreate/` gives it a message, with the same import line.

How does it know? That is the next folder.

## `.chapterjs/`: generated, ignored, safe to delete

This folder is written by the framework, and git ignores it. It holds the **types of your project**: the description of what each function receives in each folder, which is what your editor reads to complete what you type and to underline a mistake. It also keeps a small cache (what was last registered with Discord, so that starting again costs nothing) and, later, the compiled bot.

It is written when you install the project (`postinstall` runs `chapterjs sync`) and every time `chapterjs dev` starts. If your editor ever says that `event` does not exist, or that it does not know what your function receives, run `chapterjs sync` (`pnpm chapterjs sync`, or the equivalent) and reload the editor. You can also delete the folder: it is rebuilt.

## Try the editor

Open `src/commands/ping.ts` in your editor, and in `run`, type `interaction.` with the dot. The editor lists everything an interaction can do: `reply`, `defer`, `edit`, `followUp`, `delete`... Now type `interaction.replu('Pong!')` with a typo: it is underlined before you even save, with the method it does not know.

This is what "no type to write" means. Your files are TypeScript, so that the editor can do this, but every type comes from the framework. You never write one.

<Info>
  If nothing is underlined and nothing is completed, your editor is not reading
  the types. In Visual Studio Code, make sure the folder you opened is the
  project itself (the one with `package.json`), not a folder above it, and run
  `chapterjs sync` once.
</Info>

## Try the hot reload

Start the bot (`pnpm dev`) and leave it running. Change the answer in `src/commands/ping.ts`:

```ts src/commands/ping.ts
import { command } from 'chapterjs';

export default command({
  description: 'Replies with Pong!',
  async run({ interaction }) {
    await interaction.reply('Pong! 🏓');
  },
});
```

Save. The terminal says:

```text
↻ Reloaded in 12 ms, 1 command, 1 event, 1 component, a presence, messages in 2 languages loaded
```

Use `/ping` again in Discord: the new answer. You never restart the bot while you write it: every file of `src/` is watched, and a save reloads it, along with every file that imports it.

Now break the file on purpose: delete `'Pong! 🏓')` so that the line reads `await interaction.reply(;`, and save.

```text
✗ src/commands/ping.ts:6 Expression expected
⚠ Reloaded with an error: that file keeps running its last working version
```

The bot is still online, and `/ping` still answers with the last version that worked. Fix the file, save, and it reloads. A mistake never takes the bot down, so you can try things freely.

## The other files

| File                   | What it is                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `public/`              | The pictures and files your bot sends. Empty for now; a later chapter uses it.                                    |
| `node_modules/`        | The packages installed by your package manager, `chapterjs` among them. Never edit it, never commit it.           |
| `.env`, `.env.example` | The values your bot needs (the previous page).                                                                    |
| `.gitignore`           | What git leaves out: `.env`, `node_modules/`, `.chapterjs/`.                                                      |
| `package.json`         | The identity of your project: its name, its dependencies, and its scripts (`dev`, `build`, `start`, `typecheck`). |
| `tsconfig.json`        | The settings of TypeScript. It only points to `.chapterjs/`, where the real settings are; leave it as it is.      |

`chapterjs` is the only dependency of your bot. `typescript` and `@types/node` are development dependencies: they check your code in the editor and before a build, and are not needed to run the bot.

## Two naming rules for your own order

As a project grows, `src/commands/` fills up. Two names are never part of a command, an event or a component, so you can sort files your way:

<Tree>
  <Tree.Folder name="src/commands" defaultOpen>
    <Tree.File name="_shared.ts" />
    <Tree.Folder name="(fun)" defaultOpen>
      <Tree.File name="dice.ts" />
      <Tree.File name="ping.ts" />
    </Tree.Folder>
    <Tree.Folder name="(moderation)" defaultOpen>
      <Tree.File name="warn.ts" />
    </Tree.Folder>
  </Tree.Folder>
</Tree>

- **A folder in parentheses only groups files.** `(fun)/dice.ts` is still `/dice`. Discord never sees the group.
- **A name starting with `_` is private.** `_shared.ts` is never read as a command; use it for code several files share, and import it like any file.

Without the parentheses, a folder would be a subcommand: `fun/dice.ts` would be `/fun dice`. That is a real feature, used later for commands like `/mod ban`.

## Recap

- Where a file is says what it is: `src/commands/ping.ts` is `/ping`, and nothing registers it.
- Every file imports one function from `chapterjs`, which knows what to expect in its folder.
- `.chapterjs/` holds the generated types; your editor reads them; `chapterjs sync` rewrites them.
- Save a file and the bot uses it; a broken file keeps its last working version.
- `(group)` folders and `_private` files are yours to organise with.
