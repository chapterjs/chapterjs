<Note>
  How to write an event file is in [Events](/events); the events about messages and their options in [Messages](/events/messages); `event()` and its types in [event()](/reference/event).
</Note>

An event is a folder of `src/events/`. Each section below is one folder: when its files run, the intents Discord needs for it (worked out from your files, never written by you), its options, what the bot remembers for it beyond [the default](/memory), and what your function receives.

Intents are named as `chapterjs dev` prints them. Two are privileged, to enable in the [Developer Portal](/setup/discord-application): `GUILD_MEMBERS` is the Server Members Intent, `MESSAGE_CONTENT` the Message Content Intent.

## ready

| | |
| --- | --- |
| When | The bot is connected and knows every server it is in. Once per start, never again on reload. |
| Intents | None |
| Options | None |
| Remembers | The default |

<ResponseField name="user" type="User" required>
  The bot itself.
</ResponseField>
<ResponseField name="guilds" type="ReadonlyMap<Snowflake, Guild>" required>
  The servers the bot is in.

## messageCreate

| | |
| --- | --- |
| When | A message was sent, in a server or in private. By default, only by a person, in a server. |
| Intents | `MESSAGE_CONTENT` (privileged), plus `GUILD_MESSAGES` for a file that listens in servers and `DIRECT_MESSAGES` for a file that listens in private messages |
| Options | `bots`, `where` ([MessageEventOptions](/reference/event#messageeventoptions)) |
| Remembers | The default |

<ResponseField name="message" type="MemberMessage" required>
  The message that was sent. The type follows the options of the file: `MemberMessage` by default, `GuildMessage` with `bots: true`, `DmMessage` with `where: 'dm'`, `MemberMessage | PrivateMessage` with `where: 'both'` (`GuildMessage | PrivateMessage` with both options). The four are in [Message](/reference/message#types).
</ResponseField>

## messageDelete

| | |
| --- | --- |
| When | A message was deleted. By default, only in a server. |
| Intents | `GUILD_MESSAGES` for a file that listens in servers, `DIRECT_MESSAGES` for a file that listens in private messages |
| Options | `where` ([WhereEventOptions](/reference/event#whereeventoptions)) |
| Remembers | The default: no message, so `message` is `null` today |

What a file without `where` receives:

<ResponseField name="messageId" type="Snowflake" required>
  The id of the deleted message.
</ResponseField>
<ResponseField name="channelId" type="Snowflake" required>
  The id of the channel the message was in.
</ResponseField>
<ResponseField name="guildId" type="Snowflake" required>
  The id of the server.
</ResponseField>
<ResponseField name="guild" type="Guild" required>
  The server the message was in.
</ResponseField>
<ResponseField name="channel" type="GuildTextBasedChannel" required>
  The channel the message was in.
</ResponseField>
<ResponseField name="message" type="GuildMessage | null" required>
  The message as it was, when the bot remembered it.
</ResponseField>

With `where: 'dm'`, `guildId` and `guild` do not exist, `channel` is a `DMChannel | null` (the private conversation, when the bot knows it) and `message` a `DmMessage | null`. With `where: 'both'`, a private message comes with `guildId: null`, `guild: null`, `channel: DMChannel | null` and `message: PrivateMessage | null`, so `guild` tells the two apart.
