<Note>
  How to write an event file is in [Events](/events); the events about messages and their options in [Messages](/events/messages); `event()` and its types in [event()](/reference/event).
</Note>

An event is the `name` of an `event()` declaration. Each section below is one event: when its declarations run, the intents Discord needs for it (worked out from your files, never written by you), its options, what the bot remembers for it beyond [the default](/memory), and what your function receives.

Intents are named as `chapterjs dev` prints them. Three are privileged, to enable in the [Developer Portal](/setup/discord-application): `GUILD_MEMBERS` is the Server Members Intent, `GUILD_PRESENCES` the Presence Intent, `MESSAGE_CONTENT` the Message Content Intent.

</ResponseField>

## messageDelete

| | |
| --- | --- |
| When | A message was deleted. By default, only in a server. Messages deleted together (by a moderator, or by `bulkDelete()`) are one `messageDelete` each. |
| Intents | `GUILD_MESSAGES` for a file that listens in servers, `DIRECT_MESSAGES` for a file that listens in private messages |
| Options | `where` ([WhereEventOptions](/reference/event#whereeventoptions)) |
| Remembers | The default: no message, so `message` is `null` today |

What a file without `where` receives:

<ResponseField name="messageId" type="Snowflake" required>
  The id of the deleted message.
</ResponseField>
<ResponseField name="channelId" type="Snowflake" required>
  The id of the channel the message was in.
</ResponseField>
<ResponseField name="guildId" type="Snowflake" required>
  The id of the server.
</ResponseField>
<ResponseField name="guild" type="Guild" required>
  The server the message was in.
</ResponseField>
<ResponseField name="channel" type="GuildTextBasedChannel" required>
  The channel the message was in.
</ResponseField>
<ResponseField name="message" type="GuildMessage | null" required>
  The message as it was, when the bot remembered it.
</ResponseField>

With `where: 'dm'`, `guildId` and `guild` do not exist, `channel` is a `DMChannel | null` (the private conversation, when the bot knows it) and `message` a `DmMessage | null`. With `where: 'both'`, a private message comes with `guildId: null`, `guild: null`, `channel: DMChannel | null` and `message: PrivateMessage | null`, so `guild` tells the two apart.

## When Discord only gives an id

Some events come with the id of who did it and nothing more: removing a reaction, voting, typing in private, being interested in a scheduled event. When the bot does not know that person yet, it asks Discord once before running your files, then remembers them: `user` is always there. Like for [a channel the bot does not know](/events/messages#a-channel-the-bot-does-not-know), when Discord refuses, the event is not delivered and you are told:

```text
⚠ A reactionRemove event was not given to your files: Discord did not let the bot read the user who did it (Discord refused GET /users/{user.id}: Unknown User (10013)).
```
