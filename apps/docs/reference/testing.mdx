`scenario()` declares a test of your bot, from a `*.test.ts` file of `src/`, and `chapterjs test` runs it against a Discord in memory. Everything on this page is imported from `chapterjs/test`.

```ts src/checks/hello.test.ts
import { scenario } from 'chapterjs/test';
import { hello } from './hello';

export default scenario('hello greets', async bot => {
  const reply = await bot.use(hello, { who: bot.member('alice') });
  reply.says('Hello alice').isPublic();
});
```

```ts src/checks/hello.ts
import { command } from 'chapterjs';

export const hello = command({
  name: 'hello',
  description: 'Says hello',
  options: { who: { type: 'user', description: 'Who', required: true } },
  async run({ interaction, options }) {
    await interaction.reply(`Hello ${options.who.username}!`);
  },
});
```

<Note>
  How to test a bot, what is checked without a scenario and what the test server has is in the [guide](/testing). This page lists what exists.
</Note>

## scenario()

```ts
scenario(label: string, run: (bot: TestBot) => unknown): ScenarioDeclaration
```

Declares a test of your bot. Export the result from a `*.test.ts` file of `src/`: `chapterjs test` runs it against a Discord in memory, where the bot is in a server with a few people in it.

`bot` is the bot in its test server: `bot.use()` runs a command, `bot.click()` presses a button, `bot.say()` sends a message as someone, and what comes back says what the bot answered.

A file may export several scenarios, in a list too. The label is what the report shows: it can not be empty, and 120 characters is the most.

### ScenarioDeclaration

What `scenario()` returns: a declaration the runner finds in the exports of a file.

<ResponseField name="config" type="{ label: string; run: (bot: TestBot) => unknown }">
  What the file gave to `scenario()`, not checked yet.
</ResponseField>

## TestBot

The bot of the project, running in a Discord in memory: one server, a few people, and everything the bot does kept where the test can read it.

<ResponseField name="guild" type="{ id: string; name: string }" required>
  The test server.
</ResponseField>

<ResponseField name="me" type="TestMember" required>
  The bot itself, as a member of the server.
</ResponseField>

<ResponseField name="owner" type="TestMember" required>
  The owner of the server.
</ResponseField>

<ResponseField name="someone" type="TestMember" required>
  A person with no special rights: who does things when nobody is named.
</ResponseField>

<ResponseField name="requests" type="{ method: string; path: string; body: unknown }[]" required>
  Every request the bot sent to Discord so far.
</ResponseField>

### member()

```ts
member(name: string, options?: TestMemberOptions): TestMember
```

A person of the server, made the first time the name is given. The options only count the first time.

### role()

```ts
role(name: string, options?: TestRoleOptions): TestRole
```

A role of the server, made the first time the name is given.

### channel()

```ts
channel(name: string, options?: TestChannelOptions): TestChannel
```

A channel of the server, made the first time the name is given. `#general` exists.

### use()

```ts
use(command: CommandDeclaration, options?: OptionInputsOf<Options>, where?: TestWhere): Promise<TestReply>
use(command: MenuDeclaration, target: TestMenuTarget, where?: TestWhere): Promise<TestReply>
```

Uses a command, as a person would: a slash command with its options, or a menu command on what it is used on (`{ on: message }`, `{ on: member }`; a message menu is used in the channel of its message). Resolves once the bot answered.

`options` is typed from the options of the command (`OptionInputsOf`): a text, a number, `true` or `false`, one of the `choices`, a `TestMember` for a `user` option, a `TestRole` for a `role` one, a `TestChannel` for a `channel` one, a `TestFile` for an `attachment` one. It may be left out when the command requires none. What Discord would not let a person send (a required option missing, a number out of its range, a text too long, a value that is not one of the choices) fails the scenario before the bot hears of it.

### click()

```ts
click(button: ButtonTarget, where?: TestWhere): Promise<TestReply>
```

Clicks a button. Resolves once the bot answered. A button found on a message (`reply.button('Confirm')`) is clicked on that message, as a person would.

### select()

```ts
select(menu: SelectTarget, values: readonly SelectInput[], where?: TestWhere): Promise<TestReply>
```

Picks values in a select menu. Resolves once the bot answered. `values` are texts for a menu of texts (its option values), people, roles or channels for the others; the `min` and `max` of the menu are enforced.

### submit()

```ts
submit(form: FormTarget<Fields>, fields?: FieldInputsOf<Fields>, where?: TestWhere): Promise<TestReply>
```

Fills in and sends a form. Resolves once the bot answered. `fields` is typed from the fields of the form (`FieldInputsOf`): a text for a `text` field, a list of option values for a `select` or `checkboxes` one, one option value for a `radio` one, `true` or `false` for a `checkbox`, people, roles or channels for the others, files for a `files` field. A field left out stays empty; a required one left out fails the scenario, as the Discord app would refuse to send the form.

### suggest()

```ts
suggest(command: CommandDeclaration, option: string, typed: string, where?: TestWhere): Promise<TestSuggestion[]>
```

Types in an option with suggestions, and gets what the bot suggests.

### say()

```ts
say(content: string, where?: TestWhere): Promise<TestMessage>
```

Sends a message as a person. Resolves once the bot handled it.

### react()

```ts
react(message: TestMessage, emoji: string, where?: { by?: TestMember }): Promise<void>
```

Reacts to a message as a person. Resolves once the bot handled it.

### join()

```ts
join(member: string | TestMember, options?: TestMemberOptions): Promise<TestMember>
```

Makes a person join the server. Resolves once the bot handled it.

### leave()

```ts
leave(member: TestMember): Promise<void>
```

Makes a person leave the server. Resolves once the bot handled it.

### run()

```ts
run(task: TaskDeclaration, at?: Date): Promise<void>
```

Runs a task now, as if its time had come. Resolves once it is done.

### settle()

```ts
settle(): Promise<void>
```

Waits for everything the bot started to be done.

Everything but what waits for the test to act: a function waiting for a message, a click or a reaction (`waitForMessage()`...) is left waiting, and `use()`, `say()`, `click()`... resolve meanwhile.

### endWaits()

```ts
endWaits(): Promise<void>
```

Ends everything the bot waits for (`waitForMessage()`, `waitForClick()`...) as if its time was up: time does not pass in the test server. Resolves once the bot handled it.

## TestAssertions

What is checked of a message or an answer. Each check throws a `TestFailure` with a plain sentence when it fails, and returns what it checked otherwise, so checks chain.

### saysExactly()


### isEphemeral()

```ts

```

### isPublic()

## Types

- `OptionInputsOf<Options>`: the options of a command as a test fills them in. A required option can not be left out.
- `FieldInputsOf<Fields>`: the fields of a form as a test fills them in: a field left out stays empty.
- `SelectInput`: what a test picks in a menu: texts, or people, roles and channels.
- `TestMenuTarget<Type>`: what a menu command is used on in a test: `{ on }`, a `TestMember` for a `'user'` menu, a `TestMessage` for a `'message'` menu.
- `ButtonTarget`: a button, as a test names it: the declaration, an instance, or one found on a message (`reply.button('Confirm')`).
- `SelectTarget`: a menu, the same way (`reply.menu()`).
- `FormTarget<Fields>`: a form, the same way (`reply.form`).
- `TestChannelType`: `'text' | 'announcement' | 'voice' | 'category' | 'forum'`.
- `TestFailure`: an expectation of a test that the bot did not meet. What every check throws, with a plain sentence: the report shows it with the line of the scenario.
