title: 'Message options'
description: 'Everything a message can contain when you send, reply, edit, answer a command or post with a webhook'
---

`channel.send()`, `message.reply()`, `user.send()`, `member.send()` and the first message of `forum.createPost()` take a `MessageInput`: a text, or a `MessageOptions` object. `interaction.reply()` and `webhook.send()` take the same options with a few changes, listed at the end.

```ts
import type { TextChannel } from 'chapterjs';

async function example(channel: TextChannel) {
  await channel.send('Hello!');
  await channel.send({
    content: 'Here is the report',
    embeds: [{ title: 'Weekly report', description: 'Everything went well.' }],
    files: [{ name: 'report.txt', data: 'The full report' }],
    silent: true,
  });
}
```

<Note>
  How to use all of this is in [Sending messages](/messages). The messages you receive are described in [Message](/reference/message).
</Note>

## MessageInput

```ts
type MessageInput = string | MessageOptions
```

A message to send: its text, or its options.

## MessageOptions

What a message can contain, and how it is sent. A message needs at least a content, an embed, a file, a component, a sticker or a poll.

<ResponseField name="content" type="string">
  The text of the message (up to 2000 characters).
</ResponseField>

<ResponseField name="embeds" type="(Embed | EmbedDeclaration<[]>)[]">
  Up to 10 embeds: written here, or declared with `embed()`. See [Embed](#embed) and [embed()](/reference/embed).
</ResponseField>

<ResponseField name="components" type="MessageComponent[]">
  Buttons, select menus and layout components, made by ChapterJS: components declared with `button()`, `select()`... and `row()`, `text()`, `container()`... See [Components](#components).
</ResponseField>

<ResponseField name="files" type="(FileInput | AssetFile)[]">
  Up to 10 files to attach: their content, or `asset()` for a file of `public/`. See [FileInput](#fileinput) and [asset()](#asset).
</ResponseField>

<ResponseField name="allowedMentions" type="AllowedMentions">
  Who the message is allowed to notify. See [AllowedMentions](#allowedmentions).
</ResponseField>

<ResponseField name="stickers" type="Snowflake[]">
  The ids of up to 3 stickers of the server.
</ResponseField>

<ResponseField name="poll" type="PollInput">
  A poll to attach to the message. See [PollInput](#pollinput).
</ResponseField>

<ResponseField name="tts" type="boolean">
  Reads the message aloud.
</ResponseField>

<ResponseField name="silent" type="boolean">
  Sends the message without a notification sound.
</ResponseField>

<ResponseField name="suppressEmbeds" type="boolean">
  Does not show the previews of the links of the message.
</ResponseField>

<ResponseField name="replyTo" type="Snowflake | { id: Snowflake }">
  The message to reply to.
</ResponseField>

[Discord documentation](https://docs.discord.com/developers/resources/message#create-message)

## MessageEditOptions

What can be changed in a message that was already sent: `message.edit()` takes a text, or these fields of `MessageOptions`. Only what you pass changes: an empty list removes the embeds or the components, and the files you pass replace the ones of the message.

<ResponseField name="content" type="string">
  The text of the message (up to 2000 characters).
</ResponseField>

<ResponseField name="embeds" type="(Embed | EmbedDeclaration<[]>)[]">
  Up to 10 embeds: written here, or declared with `embed()`.
</ResponseField>

<ResponseField name="components" type="MessageComponent[]">
  Buttons, select menus and layout components, made by ChapterJS: components declared with `button()`, `select()`... and `row()`, `text()`, `container()`...
</ResponseField>

<ResponseField name="files" type="(FileInput | AssetFile)[]">
  Up to 10 files to attach: their content, or `asset()` for a file of `public/`.
</ResponseField>

<ResponseField name="allowedMentions" type="AllowedMentions">
  Who the message is allowed to notify.
</ResponseField>

<ResponseField name="suppressEmbeds" type="boolean">
  Does not show the previews of the links of the message. `false` shows them again.
</ResponseField>

[Discord documentation](https://docs.discord.com/developers/resources/message#edit-message)

## FileInput

A file to attach to a message. Each file is sent with the message, and an embed can show it with `attachment://<name>` as the `url` of its `image` or `thumbnail`.

<ResponseField name="name" type="string" required>
  The name of the file, with its extension: `chart.png`.
</ResponseField>

<ResponseField name="data" type="Blob | Uint8Array | ArrayBuffer | string" required>
  The content of the file.
</ResponseField>

<ResponseField name="description" type="string">
  What the file shows, for people who can't see it.
</ResponseField>

<ResponseField name="spoiler" type="boolean">
  Hides the file until it is clicked.
</ResponseField>

<ResponseField name="contentType" type="string">
  The media type of the file (`image/png`); guessed from the name when missing.
</ResponseField>

[Discord documentation](https://docs.discord.com/developers/reference#uploading-files)

## asset()

```ts
asset(path: PublicFile, options?: AssetOptions): AssetFile
```

A file of the `public/` folder of the project, to send with a message: `files: [asset('photos/monday.png')]`. The file is read when the message is sent, so a missing file is an error there.

`asset` is imported from `'chapterjs'` like everything else, and typed for your project by the `.chapterjs/` folder: `PublicFile` is the union of the paths of every file of `public/`, so the editor lists them and underlines one that does not exist. The folder is read again by `chapterjs dev` every time a file is added or removed, and by `chapterjs sync` and `chapterjs build`. How to use it is in [Files](/messages#files).

### PublicFile

```ts
type PublicFile = 'logo.png' | 'photos/monday.png' | ...
```

A file of the `public/` folder of your project, as a path from it: `'photos/monday.png'`. `never` while the folder is empty or missing.

<ResponseField name="description" type="string">
  What the file shows, for people who can't see it.
</ResponseField>

<ResponseField name="spoiler" type="boolean">
  Hides the file until it is clicked.
</ResponseField>

<ResponseField name="contentType" type="string">
  The media type of the file (`image/png`); guessed from the name when missing.
</ResponseField>

## Embed

  The title of the embed (256 characters at most).
</ResponseField>

<ResponseField name="description" type="string">

</ResponseField>

<ResponseField name="url" type="string">
  The link the title opens.
</ResponseField>

<ResponseField name="timestamp" type="string">

<ResponseField name="color" type="number">

### Embed limits

| Limit | Maximum |
| --- | --- |
| Embeds per message | 10 |
| `title` | 256 characters |
| `description` | 4096 characters |
| `fields` | 25 |
| `fields[].name` | 256 characters |
| `fields[].value` | 1024 characters |
| `footer.text` | 2048 characters |
| `author.name` | 256 characters |
| All of the above, for every embed of a message | 6000 characters |

Going over one throws an error that names the field, before anything is sent: see [Limits and errors](#limits-and-errors).

## AllowedMentions

Who a message is allowed to notify. Without it, a message notifies everyone it mentions.

<ResponseField name="parse" type="('roles' | 'users' | 'everyone')[]">
  The kinds of mentions of the text that notify: `[]` notifies nobody.
</ResponseField>

<ResponseField name="roles" type="Snowflake[]">
  The ids of the roles to notify (100 at most).
</ResponseField>

<ResponseField name="users" type="Snowflake[]">
  The ids of the users to notify (100 at most).
</ResponseField>

<ResponseField name="repliedUser" type="boolean">
  For a reply, whether to notify the author of the message replied to. By default `false`.
</ResponseField>

[Discord documentation](https://docs.discord.com/developers/resources/message#allowed-mentions-object)

## PollInput

A poll to attach to a message.

<ResponseField name="question" type="PollMedia" required>
  The question of the poll. Only `text` is supported.
  <Expandable title="PollMedia">
    <ResponseField name="text" type="string">
      The text.
    </ResponseField>
    <ResponseField name="emoji" type="{ id?: Snowflake | null; name?: string | null }">

    </ResponseField>
  </Expandable>

<ResponseField name="answers" type="PollAnswer[]" required>
  Each of the answers available in the poll, up to 10.
  <Expandable title="PollAnswer">
    <ResponseField name="pollMedia" type="PollMedia" required>

    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="duration" type="number">
  How many hours the poll stays open, up to 32 days. By default 24.
</ResponseField>

<ResponseField name="allowMultiselect" type="boolean">

</ResponseField>

<ResponseField name="layoutType" type="1">
  The layout of the poll. There is only one: `1`, the default.
</ResponseField>

## Components

`components` only takes what ChapterJS made: the buttons, menus and forms declared with `button()`, `select()` and `modal()`, and the layout helpers (`row()`, `linkButton()`, `text()`, `section()`, `container()`...). A plain object is refused before anything is sent, so no id is ever written by hand. Buttons that follow each other are put in rows of 5; a menu gets a row of its own.

A message with a text, a section, a gallery, a file, a separator or a container is built with components only: Discord shows no `content` and no `embeds`, and the message says so before leaving if you pass one. The pieces and their types are listed in [Layout](/reference/layout); how to use them is in [Buttons](/components) and [Embeds and layout](/components/embeds).

[Discord documentation](https://docs.discord.com/developers/components/reference)

## InteractionReplyOptions

The options of an answer: everything a message takes, except `replyTo` and `stickers`. It is what `interaction.reply()` and `interaction.followUp()` take, as a text or as an object (`InteractionReply`); `interaction.edit()` takes a [`MessageEditOptions`](#messageeditoptions). See [Interaction](/reference/interaction).

<ResponseField name="ephemeral" type="boolean">
  Only show the answer to who used the command. By default: what the command says with its own `ephemeral`, else visible to everyone.
</ResponseField>

[Discord documentation](https://docs.discord.com/developers/interactions/receiving-and-responding#create-interaction-response)

## WebhookMessageOptions

What a message posted with a webhook can contain: everything a message takes, except `replyTo`, and these. It is what [`webhook.send()`](/reference/webhook) takes, as a text or as an object.

<ResponseField name="username" type="string">
  Shows this name instead of the name of the webhook.
</ResponseField>

<ResponseField name="avatarURL" type="string">
  Shows this avatar instead of the avatar of the webhook.
</ResponseField>

<ResponseField name="threadId" type="Snowflake">
  Sends the message in this thread of the channel of the webhook.
</ResponseField>

[Discord documentation](https://docs.discord.com/developers/resources/webhook#execute-webhook)

## Limits and errors

Every message is checked before it is sent, so a mistake is an error in your code with a plain message, not a refusal of Discord. The numbers are the ones of your message.

| What was wrong | The error |
| --- | --- |
| Not a text nor an object | `A message is a text or an object like { content: "Hello" }, got number.` |
| `content` is not a text | `The content of a message is a text, got number.` |
| `content` over 2000 characters | `The message is 2345 characters long: Discord accepts 2000 at most. Split it in several messages or put the text in a file.` |
| More than 10 embeds | `A message has 10 embeds at most, got 11.` |
| A text of an embed too long | `The title of embed 1 is 300 characters long: Discord accepts 256 at most.` (also `description`, `footer text`, `author name`, `name of field 3`, `value of field 3`) |
| More than 25 fields in an embed | `Embed 1 has 26 fields: Discord accepts 25 at most.` |
| The embeds over 6000 characters together | `The embeds of the message contain 6100 characters in total: Discord accepts 6000 at most.` |
| More than 3 stickers | `A message has 3 stickers at most, got 4.` |
| More than 10 files | `A message has 10 files at most, got 11.` |
| Nothing to send (when sending, not editing) | `The message is empty: give it a content, an embed, a file, a component, a sticker or a poll.` |
| A file without a name | `Every file needs a name with its extension, like "chart.png".` |

The text of an embed is counted without the spaces around it. What these checks don't cover (a wrong `customId`, an unknown sticker...) is refused by Discord with a [`DiscordApiError`](/reference/errors#discordapierror) that says which field.
