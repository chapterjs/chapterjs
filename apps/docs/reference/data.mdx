Some things have no class of their own: you get them as plain objects, with the fields of Discord written in camelCase. They have no methods, and nothing on them sends a request.

<Note>
  The structures that have a page of their own are listed in the [overview](/reference). What a message contains when you send one is in [Message options](/reference/message-options).
</Note>

Two things hold everywhere on this page:

- A date is a `string` in ISO 8601 (`'2026-10-06T12:00:00.000000+00:00'`): `new Date(value)` turns it into a `Date`.
- A user inside plain data is plain data too (`id`, `username`, `globalName`, `avatar`...), not a [`User`](/reference/user). Only `Ban` holds a real `User`.

```ts
import type { Message } from 'chapterjs';

function images(message: Message) {
  return message.attachments.filter(file => file.contentType?.startsWith('image/'));
}
```

## Attachment

A file attached to a message. You read them in `message.attachments`.

<ResponseField name="id" type="Snowflake" required>The id of the attachment.</ResponseField>
<ResponseField name="filename" type="string" required>The name of the file.</ResponseField>
<ResponseField name="title" type="string">The title of the file.</ResponseField>
<ResponseField name="description" type="string">What the file shows, for people who can't see it (1024 characters at most).</ResponseField>
<ResponseField name="contentType" type="string">The media type of the file (`image/png`).</ResponseField>
<ResponseField name="size" type="number" required>The size of the file, in bytes.</ResponseField>
<ResponseField name="url" type="string" required>The URL of the file.</ResponseField>
<ResponseField name="proxyUrl" type="string" required>The URL of the file through the proxy of Discord.</ResponseField>
<ResponseField name="height" type="number | null">The height, for an image or a video.</ResponseField>
<ResponseField name="width" type="number | null">The width, for an image or a video.</ResponseField>
<ResponseField name="placeholder" type="string">A tiny blurred preview of an image or a video, as a thumbhash.</ResponseField>
<ResponseField name="placeholderVersion" type="number">The version of that preview.</ResponseField>
<ResponseField name="ephemeral" type="boolean">Whether the file belongs to an ephemeral message: it disappears with it.</ResponseField>
<ResponseField name="durationSecs" type="number">The length of an audio or video file, in seconds.</ResponseField>
<ResponseField name="waveform" type="string">The sampled waveform of a voice message, as base64.</ResponseField>
<ResponseField name="flags" type="number">The flags of the attachment, as a bit field.</ResponseField>
<ResponseField name="clipParticipants" type="object[]">For a clip of a stream, the users who were in the stream (plain data).</ResponseField>
<ResponseField name="clipCreatedAt" type="string">For a clip of a stream, when it was recorded.</ResponseField>
<ResponseField name="application" type="object | null">For a clip of a stream, the application that was streamed, when Discord recognized it (plain data).</ResponseField>

[Discord documentation](https://docs.discord.com/developers/resources/message#attachment-object-attachment-structure)

## Reaction

The reactions of one emoji on a message. You read them in `message.reactions`, one entry per emoji.

<ResponseField name="count" type="number" required>How many times the emoji was used, super reactions included.</ResponseField>
<ResponseField name="countDetails" type="object" required>
  The same count, split.
  <Expandable title="fields">
    <ResponseField name="normal" type="number" required>How many normal reactions.</ResponseField>
    <ResponseField name="burst" type="number" required>How many super reactions.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="me" type="boolean" required>Whether the bot reacted with this emoji.</ResponseField>
<ResponseField name="meBurst" type="boolean" required>Whether the bot super-reacted with this emoji.</ResponseField>
<ResponseField name="emoji" type="object" required>
  The emoji.
  <Expandable title="fields">
    <ResponseField name="id" type="Snowflake | null">The id of a custom emoji; `null` for a standard one.</ResponseField>
    <ResponseField name="name" type="string | null">The name of a custom emoji, or the character of a standard one.</ResponseField>
    <ResponseField name="animated" type="boolean">Whether a custom emoji is animated.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="burstColors" type="string[]" required>The colors of the super reactions, as hex text.</ResponseField>

To react or read who reacted, see [Message](/reference/message): `react()`, `fetchReactionUsers()`.

[Discord documentation](https://docs.discord.com/developers/resources/message#reaction-object-reaction-structure)

## ForumTag

A tag the posts of a forum can have. You read them in `forum.availableTags`, and pass them in `availableTags` when you [create](/reference/options#channelcreateoptions) or [edit](/reference/options#guildchanneleditoptions) a forum channel.

<ResponseField name="id" type="Snowflake" required>The id of the tag.</ResponseField>
<ResponseField name="name" type="string" required>The name of the tag (0-20 characters).</ResponseField>
<ResponseField name="moderated" type="boolean" required>Whether only members with the `ManageThreads` permission can add the tag to a post or remove it.</ResponseField>
<ResponseField name="emojiId" type="Snowflake | null" required>The id of a custom emoji of the server shown next to the tag.</ResponseField>
<ResponseField name="emojiName" type="string | null" required>A standard emoji shown next to the tag, as its character.</ResponseField>

A tag has either `emojiId` or `emojiName`, or neither.

[Discord documentation](https://docs.discord.com/developers/resources/channel#forum-tag-object-forum-tag-structure)

## ThreadMember

Someone in a thread, and since when. `thread.fetchMembers()` returns a list of them.

<ResponseField name="id" type="Snowflake">The id of the thread.</ResponseField>
<ResponseField name="userId" type="Snowflake">The id of the user.</ResponseField>
<ResponseField name="joinTimestamp" type="string" required>When the user last joined the thread.</ResponseField>
<ResponseField name="flags" type="number" required>The settings of the user for the thread, as a bit field; today only about notifications.</ResponseField>

To get the member behind it, use `guild.fetchMember(threadMember.userId)`.

[Discord documentation](https://docs.discord.com/developers/resources/channel#thread-member-object-thread-member-structure)

## PermissionOverwrite

What a role or a member is allowed or denied in one channel. You read them in `channel.permissionOverwrites`.

<ResponseField name="id" type="Snowflake" required>The id of the role or of the member.</ResponseField>
<ResponseField name="type" type="'role' | 'member'" required>Whether it applies to a role or to a member.</ResponseField>
<ResponseField name="allow" type="Permissions" required>What is allowed, whatever the server says.</ResponseField>
<ResponseField name="deny" type="Permissions" required>What is denied, whatever the server says.</ResponseField>

`allow` and `deny` are [`Permissions`](/reference/permissions) sets, so `overwrite.allow.has('SendMessages')` works. To change an overwrite, use `channel.setPermissions()` and `channel.deletePermissions()`; the `permissionOverwrites` field of [`ChannelCreateOptions`](/reference/options#channelcreateoptions) has another shape, the one Discord takes.

[Discord documentation](https://docs.discord.com/developers/resources/channel#overwrite-object-overwrite-structure)

## Ban

A ban of a server. `guild.fetchBan()` returns one, `guild.fetchBans()` a list.

<ResponseField name="user" type="User" required>Who is banned.</ResponseField>
<ResponseField name="reason" type="string | null" required>Why, when a reason was given.</ResponseField>

[Discord documentation](https://docs.discord.com/developers/resources/guild#ban-object-ban-structure)

## AuditLog

What moderators and bots did in a server: its entries, newest first, and what they refer to. `guild.fetchAuditLog()` returns one.

<ResponseField name="auditLogEntries" type="object[]" required>
  The entries, from the most recent to the oldest.
  <Expandable title="fields of an entry">
    <ResponseField name="id" type="Snowflake" required>The id of the entry.</ResponseField>
    <ResponseField name="actionType" type="AuditLogEvent" required>What happened: a value of [`AuditLogEvent`](/reference/enums#auditlogevent).</ResponseField>
    <ResponseField name="targetId" type="string | null" required>The id of what was affected: a webhook, a user, a role...</ResponseField>
    <ResponseField name="userId" type="Snowflake | null" required>The id of the user or the app that did it.</ResponseField>
    <ResponseField name="reason" type="string">The reason given (1-512 characters).</ResponseField>
    <ResponseField name="changes" type="object[]">
      What changed on the target.
      <Expandable title="fields of a change">
        <ResponseField name="key" type="string" required>The name of what changed, with a few exceptions Discord lists.</ResponseField>
        <ResponseField name="oldValue" type="unknown">The value before.</ResponseField>
        <ResponseField name="newValue" type="unknown">The value after.</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="options" type="object">
      More details for some kinds of entries. Every field can be missing; counts and days are text, as Discord sends them.
      <Expandable title="fields">
        <ResponseField name="applicationId" type="Snowflake">The id of the app whose permissions were changed.</ResponseField>
        <ResponseField name="autoModerationRuleName" type="string">The name of the auto moderation rule that was triggered.</ResponseField>
        <ResponseField name="autoModerationRuleTriggerType" type="string">What triggers that rule.</ResponseField>
        <ResponseField name="channelId" type="Snowflake">The channel where it happened.</ResponseField>
        <ResponseField name="count" type="string">How many things were affected.</ResponseField>
        <ResponseField name="deleteMemberDays" type="string">After how many days of inactivity members were pruned.</ResponseField>
        <ResponseField name="id" type="Snowflake">The id of the role or member whose overwrite changed.</ResponseField>
        <ResponseField name="membersRemoved" type="string">How many members the prune removed.</ResponseField>
        <ResponseField name="messageId" type="Snowflake">The id of the message that was pinned or unpinned.</ResponseField>
        <ResponseField name="roleName" type="string">The name of the role, when `type` is `"0"`.</ResponseField>
        <ResponseField name="type" type="string">Whose overwrite changed: `"0"` a role, `"1"` a member.</ResponseField>
        <ResponseField name="integrationType" type="string">The kind of integration that did it.</ResponseField>
        <ResponseField name="status" type="string">The new status of the voice channel.</ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="users" type="object[]" required>The users the entries refer to (plain data).</ResponseField>
<ResponseField name="webhooks" type="object[]" required>The webhooks the entries refer to (plain data).</ResponseField>
<ResponseField name="threads" type="object[]" required>The threads the entries refer to (plain data).</ResponseField>
<ResponseField name="integrations" type="object[]" required>The integrations the entries refer to, partially (plain data).</ResponseField>
<ResponseField name="applicationCommands" type="object[]" required>The commands the entries refer to (plain data).</ResponseField>
<ResponseField name="autoModerationRules" type="AutoModerationRule[]" required>The auto moderation rules the entries refer to.</ResponseField>
<ResponseField name="guildScheduledEvents" type="ScheduledEvent[]" required>The scheduled events the entries refer to.</ResponseField>

[Discord documentation](https://docs.discord.com/developers/resources/audit-log#audit-log-object-audit-log-structure)

## ScheduledEvent

An event scheduled in a server: when it happens, where, and how often. `guild.fetchScheduledEvents()` returns a list, `guild.createScheduledEvent()` the one it created.

<ResponseField name="id" type="Snowflake" required>The id of the event.</ResponseField>
<ResponseField name="guildId" type="Snowflake" required>The id of the server.</ResponseField>
<ResponseField name="channelId" type="Snowflake | null" required>The id of the channel where the event takes place; `null` when it takes place outside Discord.</ResponseField>
<ResponseField name="creatorId" type="Snowflake | null">The id of the user who created the event.</ResponseField>
<ResponseField name="name" type="string" required>The name of the event (1-100 characters).</ResponseField>
<ResponseField name="description" type="string | null">The description of the event (1-1000 characters).</ResponseField>
<ResponseField name="scheduledStartTime" type="string" required>When the event starts.</ResponseField>
<ResponseField name="scheduledEndTime" type="string | null" required>When the event ends; always set for an event outside Discord.</ResponseField>
<ResponseField name="privacyLevel" type="2" required>Who can see the event: `2`, the members of the server.</ResponseField>
<ResponseField name="status" type="1 | 2 | 3 | 4" required>`1` scheduled, `2` active, `3` completed, `4` canceled.</ResponseField>
<ResponseField name="entityType" type="1 | 2 | 3" required>Where it takes place: `1` a stage channel, `2` a voice channel, `3` outside Discord.</ResponseField>
<ResponseField name="entityId" type="Snowflake | null" required>The id of what the event is tied to, when there is one.</ResponseField>
<ResponseField name="entityMetadata" type="object | null" required>
  More about the place.
  <Expandable title="fields">
    <ResponseField name="location" type="string">Where the event takes place, for an event outside Discord (1-100 characters).</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="creator" type="object">The user who created the event (plain data).</ResponseField>
<ResponseField name="userCount" type="number">How many users are interested in the event.</ResponseField>
<ResponseField name="image" type="string | null">The hash of the cover image.</ResponseField>
<ResponseField name="recurrenceRule" type="object | null" required>
  How often the event repeats; `null` when it happens once.
  <Expandable title="fields">
    <ResponseField name="start" type="string" required>When the repetition starts.</ResponseField>
    <ResponseField name="end" type="string | null" required>When the repetition ends.</ResponseField>
    <ResponseField name="frequency" type="0 | 1 | 2 | 3" required>`0` yearly, `1` monthly, `2` weekly, `3` daily.</ResponseField>
    <ResponseField name="interval" type="number" required>The spacing between two occurrences, in units of `frequency`: weekly with an interval of `2` is every other week.</ResponseField>
    <ResponseField name="byWeekday" type="number[] | null" required>The days of the week it repeats on, from `0` (Monday) to `6` (Sunday).</ResponseField>
    <ResponseField name="byNWeekday" type="object[] | null" required>Days of a given week of the month: `{ n, day }`, with `n` the week (1-5) and `day` the weekday.</ResponseField>
    <ResponseField name="byMonth" type="number[] | null" required>The months it repeats on, from `1` (January) to `12` (December).</ResponseField>
    <ResponseField name="byMonthDay" type="number[] | null" required>The days of the month it repeats on.</ResponseField>
    <ResponseField name="byYearDay" type="number[] | null" required>The days of the year it repeats on (1-364).</ResponseField>
    <ResponseField name="count" type="number | null" required>How many times it repeats before stopping.</ResponseField>
  </Expandable>
</ResponseField>

[Discord documentation](https://docs.discord.com/developers/resources/guild-scheduled-event#guild-scheduled-event-object-guild-scheduled-event-structure)

## AutoModerationRule

A rule Discord applies by itself to the messages of a server: what triggers it, and what it does then. `guild.fetchAutoModerationRules()` returns a list.

<ResponseField name="id" type="Snowflake" required>The id of the rule.</ResponseField>
<ResponseField name="guildId" type="Snowflake" required>The id of the server.</ResponseField>
<ResponseField name="name" type="string" required>The name of the rule.</ResponseField>
<ResponseField name="creatorId" type="Snowflake" required>The id of the user who created the rule.</ResponseField>
<ResponseField name="eventType" type="1 | 2" required>When the rule is checked: `1` a member sends or edits a message, `2` a member edits their profile.</ResponseField>
<ResponseField name="triggerType" type="1 | 3 | 4 | 5 | 6" required>What triggers it: `1` words from a list, `3` spam, `4` words from a preset list of Discord, `5` too many mentions, `6` words from a list in the profile of a member.</ResponseField>
<ResponseField name="triggerMetadata" type="object" required>
  The details of the trigger. Which fields are there depends on `triggerType`.
  <Expandable title="fields">
    <ResponseField name="keywordFilter" type="string[]">The words or parts of words searched for (1000 at most).</ResponseField>
    <ResponseField name="regexPatterns" type="string[]">The regular expressions matched against the content (10 at most).</ResponseField>
    <ResponseField name="presets" type="number[]">The preset lists of Discord searched for: `1` profanity, `2` sexual content, `3` slurs.</ResponseField>
    <ResponseField name="allowList" type="string[]">The words that never trigger the rule (100 or 1000 at most, depending on the trigger).</ResponseField>
    <ResponseField name="mentionTotalLimit" type="number">How many different roles and users a message may mention (50 at most).</ResponseField>
    <ResponseField name="mentionRaidProtectionEnabled" type="boolean">Whether mention raids are detected by themselves.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="actions" type="object[]" required>
  What happens when the rule is triggered.
  <Expandable title="fields of an action">
    <ResponseField name="type" type="1 | 2 | 3 | 4" required>`1` block the message, `2` send an alert in a channel, `3` time the member out, `4` block the member from using text, voice and other interactions.</ResponseField>
    <ResponseField name="metadata" type="object">
      What the action needs.
      <Expandable title="fields">
        <ResponseField name="channelId" type="Snowflake">The channel where the alert is sent.</ResponseField>
        <ResponseField name="durationSeconds" type="number">How long the timeout lasts, in seconds.</ResponseField>
        <ResponseField name="customMessage" type="string | null">What the member is told when their message is blocked.</ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="enabled" type="boolean" required>Whether the rule is on.</ResponseField>
<ResponseField name="exemptRoles" type="Snowflake[]" required>The ids of the roles the rule ignores (20 at most).</ResponseField>
<ResponseField name="exemptChannels" type="Snowflake[]" required>The ids of the channels the rule ignores (50 at most).</ResponseField>

[Discord documentation](https://docs.discord.com/developers/resources/auto-moderation#auto-moderation-rule-object-auto-moderation-rule-structure)

## Sticker

A sticker: one of a server, or a standard one from a pack. `guild.fetchStickers()` returns the ones of a server.

<ResponseField name="id" type="Snowflake" required>The id of the sticker.</ResponseField>
<ResponseField name="packId" type="Snowflake">For a standard sticker, the id of its pack.</ResponseField>
<ResponseField name="name" type="string" required>The name of the sticker.</ResponseField>
<ResponseField name="description" type="string | null" required>The description of the sticker.</ResponseField>
<ResponseField name="tags" type="string" required>The words that suggest the sticker when typing (200 characters at most).</ResponseField>
<ResponseField name="type" type="1 | 2" required>`1` a standard sticker from a pack, `2` a sticker of a server.</ResponseField>
<ResponseField name="formatType" type="1 | 2 | 3 | 4" required>The format of the image: `1` PNG, `2` APNG, `3` Lottie, `4` GIF.</ResponseField>
<ResponseField name="available" type="boolean">Whether the sticker of a server can be used; `false` when the server lost the boosts it needed.</ResponseField>
<ResponseField name="guildId" type="Snowflake">The id of the server that owns the sticker.</ResponseField>
<ResponseField name="user" type="object">The user who uploaded the sticker (plain data).</ResponseField>
<ResponseField name="sortValue" type="number">The place of a standard sticker in its pack.</ResponseField>

To send one, pass its id in the `stickers` of a message: see [Message options](/reference/message-options).

[Discord documentation](https://docs.discord.com/developers/resources/sticker#sticker-object-sticker-structure)
