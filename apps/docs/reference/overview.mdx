ChapterJS gives your code **structures**: a server, a member, a channel, a message... Each one has properties to read and methods to act. Everything is typed, so your editor completes names and underlines mistakes before the bot runs.

<Note>
  You receive these structures in your [events](/events). Commands are coming in a next version.
</Note>

## Three rules to remember

<Steps>
  <Step title="A property never costs anything">
    `guild.name`, `member.roles`, `guild.channels`... read what the bot already knows. They are instant and never send a request to Discord.
  </Step>
  <Step title="A fetch method asks Discord">
    Methods that start with `fetch` return a promise. When they get one thing by its id, they look in what the bot knows first and only ask Discord if needed. Pass `{ force: true }` to always ask Discord.
  </Step>
  <Step title="Other methods act">
    `member.ban()`, `channel.send()`, `message.delete()`... do something on Discord and return a promise. Always `await` them.
  </Step>
</Steps>

```ts
import type { Guild } from 'chapterjs';

async function example(guild: Guild) {
  // Property: instant.
  console.log(guild.name, guild.roles.size);

  // Fetch: from what the bot knows, or else from Discord.
  const owner = await guild.fetchOwner();

  // Action: done on Discord.
  await owner.send(`Hello from ${guild.name}!`);
}
```

## Names are in camelCase

Discord names its fields like `rate_limit_per_user`. In ChapterJS you always read and write `rateLimitPerUser`: the framework translates in both directions, including inside embeds and options.

## Lists are Maps

`guild.members`, `guild.roles`, `guild.channels`, `channel.messages`... are standard JavaScript [`Map`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Map)s that you can only read, with the id as the key:

```ts
import type { Guild } from 'chapterjs';

function example(guild: Guild) {
  const role = guild.roles.get('123456789012345678');
  const names = [...guild.channels.values()].map(channel => channel.name);
  const bots = [...guild.members.values()].filter(member => member.user.bot);
  return { role, names, bots };
}
```

## Ids

A Discord id (a "snowflake") is a text made of digits, like `'175928847299117063'`. Never store one as a number: it is too big and would lose precision.

Everywhere a method takes a user, a role, a channel or a message, you can pass either its id or the structure itself.

## The reason

Actions that moderators can see in the audit log of the server accept a `reason`, shown there:

```ts
import type { GuildMember } from 'chapterjs';

async function example(member: GuildMember) {
  await member.kick('Spamming invite links');
  await member.ban({ reason: 'Raid', deleteMessageSeconds: 3600 });
}
```

## Limits are checked for you

What you pass is checked before it is sent: a message that is too long, an invalid image size or a timeout of more than 28 days throws an error that says what the limit is. Discord's rate limits are handled by the framework: a request simply waits for its turn.

When Discord refuses an action (a missing permission, something that no longer exists...), the method throws: see [Errors](/reference/errors).

## Logging

`console.log(guild)` shows the data of a structure with camelCase names. `structure.toJSON()` returns the same data as a plain object.
