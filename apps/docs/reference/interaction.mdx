---
title: 'Interaction'
description: 'Someone used something of the bot and waits for an answer: reply, defer, edit, follow up'
---

An `Interaction` is what you answer with: the `interaction` of a [command](/commands) is a `CommandInteraction`. Discord wants a first answer within 3 seconds, and accepts edits and other messages for 15 minutes.

```ts
import type { CommandInteraction } from 'chapterjs';

export async function deny(interaction: CommandInteraction, why: string) {
  // Only the person sees it, whatever the command says.
  await interaction.reply({ content: `Sorry: ${why}`, ephemeral: true });
}
```

<Note>
  You never create an interaction: your `run` function receives one. This page lists everything it has; how to answer well (when to defer, ephemeral answers, what happens when `run` throws) is in [Answering](/commands/answering).
</Note>

### CommandInteraction

Someone used a slash command. It has everything above, plus:

<ResponseField name="commandName" type="string">
  The command as the person typed it: `/mod ban`.
</ResponseField>

### In a server, in private

What a command receives is more precise than `CommandInteraction`, and follows the `where` of the command:

| Type | For | What changes |
| --- | --- | --- |
| `GuildCommandInteraction` | A slash command used in a server: what a command receives by default (`where: 'guild'`). Discord sends the server, the member and the channel with it. | `guildId` is a `Snowflake`, `guild` is a `Guild`, `member` is a `GuildMember`, `channel` is a `GuildTextBasedChannel` |
| `DmCommandInteraction` | A slash command that is only used in private messages with the bot (`where: 'dm'`): nothing about a server exists on it. | `guildId`, `guild` and `member` do not exist; `channel` is a `DMChannel` |
| `PrivateCommandInteraction` | A slash command used in a private message with the bot, for a command that works in both places (`where: 'both'`): there is no server, which is how it is told apart from `GuildCommandInteraction`. | `guildId`, `guild` and `member` are `null`; `channel` is a `DMChannel` |

With `where: 'both'`, `run` receives `GuildCommandInteraction | PrivateCommandInteraction`: one `if (interaction.guild)` narrows everything.

[Discord documentation](https://docs.discord.com/developers/interactions/receiving-and-responding#interaction-object-interaction-structure)

## Helpers

### toJSON()

```ts
toJSON(): object
```

The data of the interaction, without its token: a token is a secret. `console.log(interaction)` never shows it either.

## Actions

Answers are sent one after the other, in the order they were asked: you can call `reply()` and `followUp()` without waiting for the first to finish.

### reply()

```ts
reply(message: InteractionReply): Promise<Message>
```

Answers. If `defer()` was called (by you, or by the framework because the answer was taking long), this completes the pending answer.

Throws when the interaction was already answered: "This interaction was already answered. Use interaction.followUp() to send another message, or interaction.edit() to change the answer."

[Discord documentation](https://docs.discord.com/developers/interactions/receiving-and-responding#create-interaction-response)

### defer()

```ts
defer(options?: { ephemeral?: boolean }): Promise<void>
```

Tells Discord the answer is coming: the person sees "thinking…" and `reply()` can then take up to 15 minutes. The framework does it by itself when an answer takes long; call it yourself to choose when.

Does nothing when the interaction was already answered or deferred. Whether the answer is ephemeral is decided here: without `ephemeral`, it is what the command says.

### edit()

```ts
edit(message: string | MessageEditOptions): Promise<Message>
```

Changes the answer. It takes a text, or [MessageEditOptions](/reference/message-options#messageeditoptions).

Throws when there is no answer yet: "There is no answer to edit yet: call interaction.reply() first."

[Discord documentation](https://docs.discord.com/developers/interactions/receiving-and-responding#edit-original-interaction-response)

### followUp()

```ts
followUp(message: InteractionReply): Promise<Message>
```

Sends another message, after the answer.

Throws when there is no answer yet: "A follow-up comes after an answer: call interaction.reply() first."

[Discord documentation](https://docs.discord.com/developers/interactions/receiving-and-responding#create-followup-message)

### delete()

```ts
delete(): Promise<void>
```

Deletes the answer.

[Discord documentation](https://docs.discord.com/developers/interactions/receiving-and-responding#delete-original-interaction-response)

## Types

### InteractionReply

```ts
InteractionReply = string | InteractionReplyOptions
```

An answer to an interaction: its text, or its options. What `reply()` and `followUp()` take.

### InteractionReplyOptions

The options of an answer: everything a message takes, except `replyTo` and `stickers`, plus `ephemeral`. It is listed in [InteractionReplyOptions](/reference/message-options#interactionreplyoptions).

```ts
import type { CommandInteraction } from 'chapterjs';

export async function report(interaction: CommandInteraction, lines: string[]) {
  await interaction.reply({
    embeds: [{ title: 'Report', description: lines.join('\n') }],
    files: [{ name: 'report.txt', data: lines.join('\n') }],
    ephemeral: true,
  });
}
```
