ChapterJS gives your code **structures**: a server, a member, a channel, a message... Each one has properties to read and methods to act. Everything is typed, so your editor completes names and underlines mistakes before the bot runs. You never create a structure: your [commands](/commands), your [events](/events) and your [components](/components) receive them.

## Three rules

<Steps>
  <Step title="A property never costs anything">
    `guild.name`, `member.roles`, `guild.channels`... read what the bot remembers. They are instant and never send a request to Discord.
  </Step>
  <Step title="A fetch method asks Discord">
    Methods that start with `fetch` return a promise. When they get one thing by its id, they look at what the bot remembers first and only ask Discord when it is not there. Pass `{ force: true }` to ask Discord anyway.
  </Step>
  <Step title="Other methods act">
    `member.ban()`, `channel.send()`, `message.delete()`... do something on Discord and return a promise. Always `await` them.
  </Step>
</Steps>

```ts
import type { Guild } from 'chapterjs';

async function example(guild: Guild) {
  console.log(guild.name, guild.roles.size); // instant
  const owner = await guild.fetchOwner(); // remembered, or else asked to Discord
  await owner.send(`Hello from ${guild.name}!`); // done on Discord
}
```

## Names are in camelCase

Discord names its fields like `rate_limit_per_user`. In ChapterJS you always read and write `rateLimitPerUser`: the framework translates in both directions, inside embeds and options too.

## Lists are Maps

`guild.members`, `guild.roles`, `guild.channels`, `channel.messages`... are JavaScript [`Map`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Map)s that you can only read, with the id as the key:

```ts
import type { Guild } from 'chapterjs';

function example(guild: Guild) {
  const role = guild.roles.get('123456789012345678');
  const names = [...guild.channels.values()].map(channel => channel.name);
  return { role, names };
}
```

What a `Map` holds is what the bot remembers, which is not always everything: see [Memory](/memory).

## Ids

A Discord id (a `Snowflake`) is a text made of digits, like `'175928847299117063'`. Never store one as a number: it is too big and would lose precision.

Everywhere a method takes a user, a role, a channel or a message, you can pass its id or the structure itself.

## The reason

Actions that moderators can see in the audit log of the server take a `reason`, shown there:

```ts
import type { GuildMember } from 'chapterjs';

async function example(member: GuildMember) {
  await member.kick('Spamming invite links');
  await member.ban({ reason: 'Raid', deleteMessageSeconds: 3600 });
}
```

## Limits are checked for you

What you pass is checked before it is sent: a message that is too long, an image size that does not exist or a timeout of more than 28 days throws an error that says what the limit is. The rate limits of Discord are handled by the framework: a request waits for its turn.

When Discord refuses an action (a missing permission, something that no longer exists...), the method throws: see [Errors](/reference/errors).

## Logging

`console.log(guild)` shows the name of the class and the data of the structure with camelCase names. `toJSON()` returns that data as a plain object. Neither shows a secret: a [webhook](/reference/webhook) leaves its token out.
