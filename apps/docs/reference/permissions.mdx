Permissions are always written by name, like `'BanMembers'`: your editor completes them and refuses a typo. Nothing here sends a request: everything is computed from what the bot knows.

<Note>
  To require permissions before a command runs, declare them in the file of the command: see [Commands](/commands). What ChapterJS answers when the bot itself lacks a permission is in [Errors](/reference/errors#what-the-person-sees).
</Note>

```ts
import type { GuildChannel, GuildMember } from 'chapterjs';

function canPost(member: GuildMember, channel: GuildChannel) {
  const permissions = member.permissionsIn(channel);
  const missing = permissions.missing(['SendMessages', 'AttachFiles']);
  return missing.length === 0 ? 'Go ahead' : `Missing: ${missing.join(', ')}`;
}
```

## Where permissions come from

| Read | Gives | Page |
| --- | --- | --- |
| `member.permissions` | What the member can do in the server, from their roles | [GuildMember](/reference/member) |
| `member.permissionsIn(channel)` | The same, changed by what the channel allows or denies | [GuildMember](/reference/member#permissionsin) |
| `channel.permissionsFor(member)` | Same as `member.permissionsIn(channel)` | [Channels](/reference/channels) |
| `role.permissions` | What the role allows in the server | [Role](/reference/role) |
| `channel.permissionOverwrites` | What each role and member is allowed or denied in the channel | [PermissionOverwrite](/reference/data#permissionoverwrite) |

To write permissions, pass names to `guild.createRole()`, `role.edit()` ([`RoleCreateOptions`](/reference/options#rolecreateoptions), [`RoleEditOptions`](/reference/options#roleeditoptions)) and `channel.setPermissions()`.

## How they are computed

The computation follows the [permission rules of Discord](https://docs.discord.com/developers/topics/permissions#permission-overwrites), in four steps:

1. **In the server.** The owner can do everything. Otherwise a member has what the @everyone role allows, plus what each of their roles allows; a member with `Administrator` can do everything.
2. **In a channel.** The overwrites of the channel change that: first the one for @everyone, then the ones for the roles of the member combined, then the one for the member themselves. Each one removes what it denies, then adds what it allows. An administrator is never affected by overwrites.
3. **What follows.** A member who can't `ViewChannel` can do nothing in it. A member who can't `SendMessages` can't `MentionEveryone`, `SendTtsMessages`, `AttachFiles` or `EmbedLinks` either.
4. **Timed out.** A timed out member only keeps `ViewChannel` and `ReadMessageHistory`, unless they are an administrator.

`member.permissions` applies steps 1 and 4; `member.permissionsIn(channel)` and `channel.permissionsFor(member)` apply all four. A thread uses the permissions of the channel it is in.

## Permissions

A set of permissions that never changes: every operation returns a new set. Discord serializes permissions as text because they don't fit in a regular number.

```ts
import { Permissions } from 'chapterjs';

const moderator = new Permissions(['KickMembers', 'BanMembers']);
moderator.has('KickMembers'); // true
moderator.add('ModerateMembers').toArray(); // ['KickMembers', 'BanMembers', 'ModerateMembers']
```

### Properties

<ResponseField name="bits" type="bigint" required>The permissions as one number, each bit being a permission.</ResponseField>

### constructor

```ts
new Permissions(bits?: PermissionResolvable | string)
```

Builds a set from a name, a list of names, bits, another set, or the text Discord uses (`'2048'`). Without an argument, the set is empty. A name that is not a permission throws a `TypeError`:

```text
"BanMember" is not a permission. Permissions are: CreateInstantInvite, KickMembers, BanMembers, ...
```

### has()

```ts
has(permission: PermissionResolvable, options?: { checkAdmin?: boolean }): boolean
```

Whether every given permission is in the set. An administrator has every permission, unless `{ checkAdmin: false }` is passed.

### any()

```ts
any(permission: PermissionResolvable, options?: { checkAdmin?: boolean }): boolean
```

Whether at least one of the given permissions is in the set.

### missing()

```ts
missing(permission: PermissionResolvable): PermissionName[]
```

The given permissions that are not in the set, by name.

### add()

```ts
add(permission: PermissionResolvable): Permissions
```

A new set with the given permissions added.

### remove()

```ts
remove(permission: PermissionResolvable): Permissions
```

A new set without the given permissions.

### toArray()

```ts
toArray(): PermissionName[]
```

The names of the permissions in the set, in the order of the docs.

### toString()

```ts
toString(): string
```

The text Discord expects in a request.

### toJSON()

```ts
toJSON(): string
```

The text Discord expects in a request.

<Info>
  `has()`, `any()` and `missing()` answer for an administrator as if they had everything. Pass `{ checkAdmin: false }` to `has()` or `any()` to check the exact bit.
</Info>

[Discord documentation](https://docs.discord.com/developers/topics/permissions)

## PermissionResolvable

A permission, or several: by name, as bits, or as a set.

```ts
type PermissionResolvable =
  | PermissionName
  | bigint
  | Permissions
  | readonly (PermissionName | bigint)[]
```

Every method of `Permissions`, and every option that takes permissions, accepts one. Something else than a name, a bigint, a set or a list of those throws a `TypeError`:

```text
A permission is a name like "BanMembers", got number.
```

## PermissionFlags

The bit of every permission, by name: `PermissionFlags.BanMembers` is `4n` (`1n << 2n`). It is what `PermissionName` is made of, and what `bits` is read against.

```ts
import { PermissionFlags, Permissions } from 'chapterjs';

const bits = PermissionFlags.KickMembers | PermissionFlags.BanMembers;
new Permissions(bits).toArray(); // ['KickMembers', 'BanMembers']
```

You rarely need it: names do the same, readably. Use it when you work with the raw bits of Discord, for example to combine them with `|` or to compare with a number from elsewhere.

[Discord documentation](https://docs.discord.com/developers/topics/permissions#permissions-bitwise-permission-flags)

## The hierarchy

Having a permission is not always enough: a member can only kick, ban, rename or give roles to members whose highest role is below their own. `member.isHigherThan(other)` and `role.isHigherThan(other)` answer that. The same applies to your bot: its highest role must be above the member it moderates.

[Discord documentation](https://docs.discord.com/developers/topics/permissions#permission-hierarchy)
