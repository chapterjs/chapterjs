---
title: 'Guild'
description: 'Read everything about a server and manage its members, roles, channels and bans'
---

A `Guild` is a server ("guild" is the name Discord gives servers in its API). You get one as the `guild` of a [command](/reference/interaction) used in a server, with the events that happen in one, and as `member.guild`, `role.guild` or `channel.guild`.

```ts
import type { Guild } from 'chapterjs';

async function describe(guild: Guild) {
  const owner = await guild.fetchOwner();
  return `${guild.name} has ${guild.memberCount} members and belongs to ${owner.displayName}.`;
}
```

<Note>
  How your functions receive a server is in [Commands](/commands) and [Events](/events). What a server remembers about its members, and why not all of them, is in [Memory](/memory).
</Note>

## Properties

<ResponseField name="id" type="Snowflake">
  The unique id Discord gave it.
</ResponseField>

<ResponseField name="createdAt" type="Date">
  When it was created: a Discord id contains its creation date.
</ResponseField>

<ResponseField name="name" type="string">
  The name of the server.
</ResponseField>

<ResponseField name="description" type="string | null">
  The description of the server, when it has one.
</ResponseField>

<ResponseField name="ownerId" type="Snowflake">
  The id of the user who owns the server.
</ResponseField>

<ResponseField name="available" type="boolean">
  `false` during an outage of Discord: the data may be out of date.
</ResponseField>

<ResponseField name="memberCount" type="number | null">
  How many members the server has. Exact when the bot receives member events, approximate otherwise; `null` when Discord never said it.
</ResponseField>

<ResponseField name="features" type="readonly GuildFeature[]">
  What the server has enabled or unlocked (`COMMUNITY`, `VANITY_URL`...). See [GuildFeature](#guildfeature).
</ResponseField>

<ResponseField name="verificationLevel" type="VerificationLevel">
  What Discord asks of new members before they can write. See [VerificationLevel](/reference/enums#verificationlevel).
</ResponseField>

<ResponseField name="premiumTier" type="PremiumTier">
  The boost level of the server. See [PremiumTier](/reference/enums#premiumtier).
</ResponseField>

<ResponseField name="boostCount" type="number">
  How many boosts the server has.
</ResponseField>

<ResponseField name="preferredLocale" type="Locale">
  The language of the server, used for what Discord sends to it. See [Locale](/reference/enums#locale).
</ResponseField>

<ResponseField name="vanityUrlCode" type="string | null">
  The code of the custom invite link of the server, when it has one.
</ResponseField>

<ResponseField name="systemChannelId" type="Snowflake | null">
  The id of the channel where Discord posts welcome messages.
</ResponseField>

<ResponseField name="rulesChannelId" type="Snowflake | null">
  The id of the channel that shows the rules, in a community server.
</ResponseField>

<ResponseField name="afkChannelId" type="Snowflake | null">
  The id of the voice channel inactive members are moved to.
</ResponseField>

<ResponseField name="joinedAt" type="Date | null">
  When the bot joined the server, when Discord said it.
</ResponseField>

<ResponseField name="roles" type="ReadonlyMap<Snowflake, Role>">
  The roles of the server, @everyone included.
</ResponseField>

<ResponseField name="members" type="ReadonlyMap<Snowflake, GuildMember>">
  The members of the server the bot knows: the ones seen the most recently, not all of them.
</ResponseField>

<ResponseField name="channels" type="ReadonlyMap<Snowflake, GuildChannel | ThreadChannel>">
  The channels and active threads of the server.
</ResponseField>

<ResponseField name="emojis" type="ReadonlyMap<Snowflake, GuildEmoji>">
  The custom emojis of the server.
</ResponseField>

<ResponseField name="everyoneRole" type="Role">
  The @everyone role, which every member has.
</ResponseField>

<ResponseField name="me" type="GuildMember">
  The bot as a member of this server.
</ResponseField>

<Info>
  `members` only holds the members the bot has seen lately (see [Memory](/memory)). Use [`fetchMember()`](#fetchmember) to get one for sure. `me` is always there, whatever the bot remembers.
</Info>

## Helpers

These read what the bot remembers: they never send a request.

### iconURL()

```ts
iconURL(options?: ImageOptions): string | null
```

The URL of the icon of the server, when it has one. See [ImageOptions](/reference/helpers#imageoptions).

### bannerURL()

```ts
bannerURL(options?: ImageOptions): string | null
```

The URL of the banner of the server, when it has one. See [ImageOptions](/reference/helpers#imageoptions).

### splashURL()

```ts
splashURL(options?: ImageOptions): string | null
```

The URL of the invite background of the server, when it has one. See [ImageOptions](/reference/helpers#imageoptions).

### toString()

```ts
toString(): string
```

The name of the server.

### toJSON()

```ts
toJSON(): object
```

The data of Discord as a plain object, with camelCase names.

## Reading from Discord

### fetch()

```ts
fetch(): Promise<Guild>
```

Asks Discord for the latest data of the server.

[Discord documentation](https://docs.discord.com/developers/resources/guild#get-guild)

### fetchMember()

```ts
fetchMember(user: Snowflake | { id: Snowflake }, options?: { force?: boolean }): Promise<GuildMember>
```

A member of the server: from what the bot remembers, or else from Discord.

[Discord documentation](https://docs.discord.com/developers/resources/guild#get-guild-member)

### fetchMembers()

```ts
fetchMembers(options?: { limit?: number; after?: Snowflake | { id: Snowflake } }): Promise<GuildMember[]>
```

Members of the server, by pages of 1000 at most, ordered by id. Needs the Server Members intent to be enabled for the bot.

`limit` is a whole number between 1 and 1000 (the default); `after` is the id of the last member of the previous page.

[Discord documentation](https://docs.discord.com/developers/resources/guild#list-guild-members)

### searchMembers()

```ts
searchMembers(query: string, limit?: number): Promise<GuildMember[]>
```

Members whose username or nickname starts with the given text. `limit` is `1` by default.

[Discord documentation](https://docs.discord.com/developers/resources/guild#search-guild-members)

### fetchOwner()

```ts
fetchOwner(): Promise<GuildMember>
```

The member who owns the server.

### fetchBan()

## Types

### GuildFeature

What a server has enabled or unlocked, as Discord names it: one of `'ANIMATED_BANNER'`, `'ANIMATED_ICON'`, `'APPLICATION_COMMAND_PERMISSIONS_V2'`, `'AUTO_MODERATION'`, `'BANNER'`, `'COMMUNITY'`, `'CREATOR_MONETIZABLE_PROVISIONAL'`, `'CREATOR_STORE_PAGE'`, `'DEVELOPER_SUPPORT_SERVER'`, `'DISCOVERABLE'`, `'ENHANCED_ROLE_COLORS'`, `'FEATURABLE'`, `'GUILD_TAGS'`, `'GUESTS_ENABLED'`, `'INVITES_DISABLED'`, `'INVITE_SPLASH'`, `'MEMBER_VERIFICATION_GATE_ENABLED'`, `'MORE_SOUNDBOARD'`, `'MORE_STICKERS'`, `'NEWS'`, `'PARTNERED'`, `'PREVIEW_ENABLED'`, `'PRUNE_REQUIRES_ADMIN'`, `'RAID_ALERTS_DISABLED'`, `'ROLE_ICONS'`, `'ROLE_SUBSCRIPTIONS_AVAILABLE_FOR_PURCHASE'`, `'ROLE_SUBSCRIPTIONS_ENABLED'`, `'SOUNDBOARD'`, `'TICKETED_EVENTS_ENABLED'`, `'VANITY_URL'`, `'VERIFIED'`, `'VIP_REGIONS'`, `'WELCOME_SCREEN_ENABLED'`.

Discord adds features over time, so any other text is accepted too: `guild.features.includes('COMMUNITY')` is typed, and an unknown feature does not break anything.

[Discord documentation](https://docs.discord.com/developers/resources/guild#guild-object-guild-features)

### Audit log filters

What `fetchAuditLog()` takes. Every field can be left out.

<ResponseField name="userId" type="Snowflake">
  Only the entries of this user.
</ResponseField>

<ResponseField name="actionType" type="AuditLogEvent">
  Only the entries of this kind of action. See [AuditLogEvent](/reference/enums#auditlogevent).
</ResponseField>

<ResponseField name="before" type="Snowflake">
  Only the entries with an id lower than this audit log entry id.
</ResponseField>

<ResponseField name="after" type="Snowflake">
  Only the entries with an id higher than this audit log entry id.
</ResponseField>

<ResponseField name="limit" type="number">
  How many entries at most, between 1 and 100; 50 by default.
</ResponseField>

[Discord documentation](https://docs.discord.com/developers/resources/audit-log#get-guild-audit-log-query-string-params)

### Scheduled event options

What `createScheduledEvent()` takes. Dates are ISO 8601 texts (`date.toISOString()`); the image is a data URI (`data:image/png;base64,...`).

<ResponseField name="name" type="string" required>
  The name of the scheduled event.
</ResponseField>

<ResponseField name="privacyLevel" type="number" required>
  The privacy level of the scheduled event: `2` (only the members of the server).
</ResponseField>

<ResponseField name="scheduledStartTime" type="string" required>
  The time to schedule the scheduled event.
</ResponseField>

<ResponseField name="entityType" type="number" required>
  Where the event takes place: `1` in a stage channel, `2` in a voice channel, `3` somewhere else (`entityMetadata.location` then says where).
</ResponseField>

<ResponseField name="channelId" type="Snowflake">
  The channel id of the scheduled event.
</ResponseField>

<ResponseField name="entityMetadata" type="{ location?: string }">
  The entity metadata of the scheduled event: `location` is where it takes place (1-100 characters).
</ResponseField>

<ResponseField name="scheduledEndTime" type="string">
  The time when the scheduled event is scheduled to end.
</ResponseField>

<ResponseField name="description" type="string">
  The description of the scheduled event.
</ResponseField>

<ResponseField name="image" type="string">
  The cover image of the scheduled event.
</ResponseField>

<ResponseField name="recurrenceRule" type="object">
  The definition for how often this event should recur, as Discord describes it.
</ResponseField>

[Discord documentation](https://docs.discord.com/developers/resources/guild-scheduled-event#create-guild-scheduled-event-json-params)
