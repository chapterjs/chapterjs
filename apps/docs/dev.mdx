---
title: 'chapterjs dev'
description: 'Run your bot on your test server while you write it, with instant reload'
---

`chapterjs dev` runs the bot of the current folder. It is what the `dev` script of your project starts:

<CodeGroup>
```bash pnpm
pnpm dev
```

```bash npm
npm run dev
```

```bash yarn
yarn dev
```

```bash bun
bun dev
```
</CodeGroup>

```text
✓ Connected to My Server as my-bot
ℹ Intents computed from your files: GUILDS, GUILD_MESSAGES, DIRECT_MESSAGES, MESSAGE_CONTENT
✓ 2 events loaded
```

## What it needs

A `.env` file at the root of your project, with two values:

```bash .env
BOT_TOKEN=
DEV_GUILD_ID=
```

- `BOT_TOKEN`: the token of your bot, from the [Developer Portal](https://discord.com/developers/applications) → your application → **Bot** → **Reset Token**.
- `DEV_GUILD_ID`: the ID of your test server. In Discord, right-click the server → **Copy Server ID** (enable **Settings** → **Advanced** → **Developer Mode** to see it).

<Warning>
  Your token is a password: never share it, and never commit your `.env` file. Projects created with `create chapter` already ignore it in git.
</Warning>

## What it checks for you

Before connecting, `chapterjs dev` makes sure everything is in place. When something is missing, it says what and how to fix it:

<AccordionGroup>
  <Accordion title="A value of .env is missing or wrong">
    Each value is checked: empty, still the example value, or not what it should be. Fix the `.env` file and start the command again.
  </Accordion>
  <Accordion title="The token is refused">
    Discord does not recognize the token. Copy it again from the Developer Portal: a token is only shown once, and resetting it makes the old one invalid.
  </Accordion>
  <Accordion title="The bot is not in your test server">
    You get a link that adds the bot to that server. Open it, confirm, and the command goes on by itself. The link gives the bot every permission, since a test server is a playground.
  </Accordion>
  <Accordion title="A privileged intent is not enabled">
    Some [events](/events#intents-nothing-to-list) need an option enabled for your bot. You get the list of the files that need it and the link to the right page. Enable it, save, and the command goes on by itself.
  </Accordion>
</AccordionGroup>

<Info>
  The command only waits when it runs in a terminal. Started by another program, it stops with the explanation instead.
</Info>

## Instant reload

Save a file and your bot uses the new version, without disconnecting:

```text
↻ Reloaded in 12 ms, 2 events loaded
```

Every file under `src/` is watched: the ones in `src/events/` and the ones they import. A new folder or a new file is picked up as soon as it is saved.

A file with a mistake never stops your bot. The error is shown with the file and the line, and **the last version that worked keeps running** until you fix it:

```text
✗ src/events/messageCreate/ping.ts:4 Expression expected
⚠ Reloaded with an error: that file keeps running its last working version
```

When a new file needs something Discord was not asked for when connecting, the bot reconnects by itself:

```text
↻ Your files now need more from Discord (GUILD_MEMBERS): reconnecting...
✓ Reconnected, 3 events loaded
```

<Info>
  Reloading starts your files again from scratch: a variable kept in a file (a counter, a list...) goes back to its first value on every save.
</Info>

## The types of your project

When it starts, `chapterjs dev` writes the types of your project in the `.chapterjs/` folder: this is how `event` knows, in each [event folder](/events), what its function receives. The folder is ignored by git and safe to delete.

`chapterjs sync` writes them without starting the bot. Projects created with `create chapter` run it after each install, so your editor knows the types right away.

To check the types of your whole project from a terminal, use the `typecheck` script of your project:

<CodeGroup>
```bash pnpm
pnpm typecheck
```

```bash npm
npm run typecheck
```

```bash yarn
yarn typecheck
```

```bash bun
bun typecheck
```
</CodeGroup>

<Warning>
  It runs `tsc -b`. A plain `tsc` checks nothing in a ChapterJS project: your files are checked by the projects of `.chapterjs/`, which only `tsc -b` and your editor follow.
</Warning>

## Only your test server

In dev, your bot only sees the server of `DEV_GUILD_ID`: what happens in the other servers it is in is ignored. Private messages sent to the bot are still received.

## Stopping

Press `Ctrl+C`. The bot disconnects properly and goes offline at once:

```text
✓ Disconnected
```

## The symbols

| Symbol | Meaning |
| --- | --- |
| `✓` | Something worked |
| `ℹ` | Something worth knowing |
| `↻` | A reload or a reconnection |
| `⚠` | Something to look at; the bot keeps running |
| `✗` | Something failed: what happened, then what to do |
